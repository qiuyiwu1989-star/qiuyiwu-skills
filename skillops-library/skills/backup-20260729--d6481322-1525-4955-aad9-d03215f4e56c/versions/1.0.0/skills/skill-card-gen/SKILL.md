# Skill Card 生成

> v2.0 | 升级：统一十维评估+批量模式+delta对比

## 触发词

- "给 XX 做个 Skill Card" / "XX 的 Skill Card" / "技能卡片" / "批量生成Card"

## 与 skill-forge 的区别

| | skill-forge | skill-card-gen |
|---|---|---|
| 输入 | 用户需求（模糊想法） | 已存在的SKILL.md |
| 输出 | 完整的SKILL.md + 目录 | Skill Card（评估摘要） |
| 时机 | 造新技能时 | 审计/盘点时 |

## 流程

### Step 1：读取 SKILL.md

读取目标Skill的SKILL.md，提取：
- name + description + version（frontmatter）
- 核心流程（正文中的流程步骤数）
- 工具链（引用的工具/脚本/API）
- 协作关系（提到的其他Agent/Skill）
- 输出格式（有无模板/示例）
- 红线（有无禁区定义）
- references/目录内容
- memory/目录内容

### Step 2：十维评估（SMS v1.0）

**统一使用skill-audit的十维体系，废弃旧版六维。**

调用skill-audit的评估逻辑，按以下10个维度评分（1-5分），每项附一句话理由：

| # | 维度 | 权重 | 检查点 |
|---|------|------|--------|
| 1 | 清晰度 | 10% | 任务明确？边界清晰？可直接调用？ |
| 2 | 可调用性 | 10% | 有明确触发条件？触发规则可判？ |
| 3 | 可执行性 | 10% | 有步骤？有判断节点？有异常处理？ |
| 4 | 输出稳定性 | 10% | 格式一致？可被下游接力？ |
| 5 | 结果质量 | 15% | 有洞察？可执行？有判断？ |
| 6 | 复用性 | 10% | 跨项目？跨行业？ |
| 7 | 组合性 | 10% | 能与其他Skill联动？有前后关系？ |
| 8 | 可评估性 | 5% | 有量化标准？有评估规则？ |
| 9 | 安全性 | 10% | 有风险清单？有审核机制？ |
| 10 | 商业价值 | 10% | 高频？可变现？强差异化？ |

**总分 = Σ(各维度得分 × 权重) × 10**，满分50分。

### Step 3：对比上次评估（delta）

读取registry中该Skill的上次评分，计算变化：
- 总分变化（↑/↓/→）
- 各维度变化（标注升降最大的维度）
- 等级变化（如B→A）

### Step 4：生成 Card

```markdown
## Skill Card：{name} v{version}

| 属性 | 值 |
|------|-----|
| 名称 | {name} |
| 路径 | {path} |
| 描述 | {description} |
| Agent | {agent} |
| 类别 | {type_primary} |
| 成熟度 | {maturity} |
| 行数 | {lines} |
| 有📚 | {has_refs}（{refs_count}个） |
| 有🧠 | {has_mem}（{mem_count}个） |
| 有📜 | {has_scripts} |
| 有🧪 | {has_evals} |

### 十维评分

| # | 维度 | 分数 | 理由 |
|---|------|------|------|
| 1 | 清晰度 | ★★★★☆ X/5 | ... |
| 2 | 可调用性 | ★★★☆☆ X/5 | ... |
| ... | ... | ... | ... |
| 10 | 商业价值 | ★★★★★ X/5 | ... |

🎯 总分：XX/50
🏆 等级：[S/A/B/C/D] 级
📊 delta：{上次分数→本次分数} {↑/↓/→}

### ✅ 核心优点
1. ...
2. ...

### ⚠️ 改进空间
1. ...（+具体改进方向）
2. ...

### 💡 建议
{推荐使用 / 建议优化后使用 / 不推荐}
```

### Step 5：写入 registry

将评分结果更新到 `memory/skill-registry.json` 对应条目的 `scores`、`grade`、`maturity` 字段。

### Step 6：批量模式（`--all`）

一次性为所有active Skill生成Card，输出汇总表：

```
📋 全量 Skill Card · {日期}
━━━━━━━━━━━━━━━━━━━━━━━━

| Skill | 等级 | 总分 | 清晰 | 可调用 | 可执行 | 输出 | 结果 | 复用 | 组合 | 评估 | 安全 | 商业 |
|-------|------|------|------|--------|--------|------|------|------|------|------|------|------|
| skill-audit | S | 46 | 5 | 4 | 5 | 5 | 5 | 5 | 4 | 5 | 3 | 5 |
| ... | ... | ... | ... | ... | ... | ... | ... | ... | ... | ... | ... | ... |

全局平均：XX/50 | S:{N} A:{N} B:{N} C:{N} D:{N}
```

## 质量等级

| 等级 | 总分区间 | 含义 |
|------|---------|------|
| S | 45-50 | 核心资产，可产品化 |
| A | 35-44 | 可用，生产级 |
| B | 25-34 | 实验，需迭代 |
| C | 15-24 | 概念，需重构 |
| D | <15 | 无效，建议废弃 |

## 注意事项

- 每项评分必须附理由，不给模糊评价
- Card生成后自动与上次对比，标注变化
- 批量模式下每个Card独立评估，不做交叉对比
- 安全性为必检项——涉及外部发送、财务、法律的Skill必须标注风险
