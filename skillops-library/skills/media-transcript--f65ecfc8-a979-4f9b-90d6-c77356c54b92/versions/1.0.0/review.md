# media-transcript 复盘（2026-10-11）

> 目的：把「导入一条视频 → 转写 → 归档上线」从"手工能跑"升级为"可常态运行"。
> 结论：**管线可行，核心价值成立**；已补常态化入口 + 修复 4 个风险点；剩 1 个外部依赖风险（解析服务）。

## 一、管线拆解（哪一步花钱、哪一步有风险）

| 步骤 | 工具 | Token | 风险 |
|------|------|-------|------|
| 1 解析抖音链接 → 无水印直链 | `douyin.py` + `api.douyin.wtf` | 0 | ⚠️ **依赖第三方服务**（demo 账号，可能限流/下线） |
| 2 下载 mp4 | curl | 0 | 低 |
| 3 抽音 | ffmpeg | 0 | 低 |
| 4 转写（词级时间戳 + SRT） | faster-whisper（本地 CPU） | 0 | 中：~2s 音频/秒，长视频慢；专有名词易错 |
| 5 读逐字稿 → 写总结 | **LLM** | ✅ 全部消耗在此 | — |

**成本公式**：`消耗 ≈ 逐字稿 token × 3`
实测一条 19:48 视频：逐字稿 ~8k token ⇒ 一进一出 ~10k–16k token。**STT（最重的一步）本地免费**，这是整条管线便宜的根本。

## 二、发现的短板 & 已修

| # | 短板 | 处置 |
|---|------|------|
| 1 | 下载后 `audio.wav` 留盘（37M/条），常态化会堆积 | ✅ transcribe.sh 转完即删 wav（`--keep-audio` 可保留） |
| 2 | 解析服务偶发抖动会直接失败 | ✅ transcribe.sh 加 3 次重试 |
| 3 | 每次手工拼"下载→上传→签名→建骨架"，易漏 | ✅ 新增 `scripts/ingest.sh` 一条龙（到"待写总结"为止） |
| 4 | 归档去处分三处（COS/reading/video）易记混 | ✅ SKILL 已写明固定路径 + publish-video.sh |

## 三、剩下的风险（要决定）

1. **解析服务的可持续性**（最大风险）
   - 现在用公开的 `api.douyin.wtf` demo 账号。**抖音直链解析是灰产性质服务，随时可能挂/限流/收费。**
   - 常态化前建议：① 自建解析（yt-dlp + 自有 cookie，或 [douyin.wtf 开源版](https://douyin.wtf) 自部署）；② 或至少准备 2 个备用 provider。
   - 目前 `douyin.py --provider` 已支持替换，但**没做多 provider 自动 fallback**。

2. **专有名词校对**：必错（"布迪厄→不敌恶"）。目前靠人工校。可考虑：维护"人名/术语白名单"，转写后自动替换。

3. **长视频耗时**：CPU 转写 ~2s 音频/秒。1 小时视频 ≈ 30 分钟转写。可接受（可后台跑），但要有进度反馈。

4. **音质**：whisper 对背景音乐重的视频（如带 BGM 的口播）准确率下降。

## 四、常态化建议（如果确定要做）

- **入口统一**：一条命令 `bash skills/media-transcript/scripts/ingest.sh "<链接>" <slug>` → 自动到"待写总结"。
- **人机分工**：机械流程（下载/转写/上传/签名/建骨架）全自动；**只把"写总结 + 校专有名词"留给人/LLM**。
- **归档一致性**：三件套（mp4→COS / 逐字稿+总结→vault/video）固定，命名 `YYYY-MM-DD-<slug>`。
- **触发方式**：可做成"我发链接 → 我跑 ingest → 我写总结并发布"，全部在对话里完成（不需要额外 UI）。
