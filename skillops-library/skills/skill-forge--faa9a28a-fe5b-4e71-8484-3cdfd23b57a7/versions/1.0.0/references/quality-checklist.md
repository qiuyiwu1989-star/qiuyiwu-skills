# 质量检查清单（详细版）

## 一、结构完整性

### Frontmatter
- [ ] `name` 字段存在且格式正确（小写-中划线）
- [ ] `description` 存在且包含触发场景
- [ ] description不是纯功能描述，有"当用户提到XXX时"的触发语句

### 正文
- [ ] 有明确的标题层级（## / ###）
- [ ] 核心流程用数字编号（第一步、第二步...）
- [ ] 有输出格式定义（模板或示例）
- [ ] 500行以内（超了就拆references）

### 目录
- [ ] 路径为 `skills/{name}/SKILL.md`
- [ ] references/ 目录存在（如果SKILL.md>300行）
- [ ] scripts/ 目录存在（如果有可执行脚本）
- [ ] memory/ 目录存在（如果需要跨session记忆）

## 二、逻辑完整性

### 意图捕获（5个问题）
- [ ] 能力边界：这个技能让Agent能做什么
- [ ] 触发条件：什么场景下激活
- [ ] IO定义：输入格式、输出格式、媒介
- [ ] 外部依赖：API、密钥、权限、工具
- [ ] 协作关系：跟哪些Agent/技能配合

### 边界情况
- [ ] 输入为空/不完整时怎么处理
- [ ] 工具调用失败时怎么处理
- [ ] 需求模糊时怎么处理
- [ ] 有没有明确的"不做XXX"的红线

## 三、团队适配（范德团队特有）

### Agent相关
- [ ] 如果是新Agent，在 `memory/team-roster.md` 中有条目
- [ ] 如果是新Agent，spawn模板写在 `skills/founder/SKILL.md` 中
- [ ] 如果需要特殊工具权限，在SKILL.md中列出

### 飞书相关
- [ ] 如果输出到飞书文档，有 `feishu_create_doc` / `feishu_update_doc` 调用步骤
- [ ] 如果涉及飞书消息，有消息格式定义

### 记忆相关
- [ ] 如果需要跨session记忆，有memory目录和读写规则
- [ ] 如果产出需要写入二脑，有知识入库流程

### 协作相关
- [ ] 与现有Agent的分工边界清楚（不重叠、不遗漏）
- [ ] 协作协议：谁触发谁、输入输出格式、先后顺序

## 四、写作质量

- [ ] 用祈使句，不用被动句
- [ ] 关键指令有"为什么"的解释
- [ ] 有至少1个输入输出示例
- [ ] 没有过度约束（MUST/ALWAYS/NEVER出现频率<5次）
- [ ] 术语首次出现时有解释

## 五、交付检查

- [ ] SKILL.md可独立阅读理解（不需要问范德"这是什么意思"）
- [ ] 参考文件有索引（SKILL.md里指明什么时候读哪个）
- [ ] 如果有脚本，脚本可执行（有执行权限、依赖已安装）
- [ ] 目录结构完整，无多余文件
