# SKILL.md 解剖指南

## 标准结构

```markdown
---
name: {skill-name}
description: "触发条件 + 功能描述。当用户提到XXX时使用。"
---

# 技能标题

## 角色定义（可选）
你是什么、面向谁、什么风格。

## 核心流程
### 第一步：...
### 第二步：...

## 输出格式
模板或示例。

## 工具链
| 工具 | 用途 | 调用方式 |
|------|------|---------|

## 协作关系
跟谁配合、输入输出、先后顺序。

## 红线
绝对不能做的事。
```

## Frontmatter 规范

### name
- 格式：小写英文 + 中划线（`skill-forge`、`qiuqiu-teacher`）
- 不能用中文、空格、下划线
- 全局唯一

### description
- 这是**触发机制**，不是功能描述
- 写法："做什么。当用户提到A、B、C时使用。"
- 宁可写得"pushy"一点——LLM倾向于under-trigger
- 示例对比：

| ❌ 弱 | ✅ 强 |
|------|-------|
| 处理合同 | 合同审核工具。当用户发送合同、协议、签约文件时，务必使用此技能审查条款风险，特别是IP和时间条款 |
| 做录音分析 | 录音分析专家。当用户发送录音转写、会议记录、语音文字稿时，立即使用此技能进行深度分析 |

## 渐进式加载三层结构

| 层 | 内容 | 大小 | 何时加载 |
|---|------|------|---------|
| Metadata | name + description | ~100字 | 始终 |
| SKILL.md正文 | 完整流程 | <500行 | 触发时 |
| References | 延伸内容 | 无限制 | 按需读取 |

**为什么要控制在500行：** LLM的注意力在长文本中会稀释。超过500行的SKILL.md，关键指令容易被忽略。

**怎么拆：** 把"领域知识"、"角色详细提示词"、"模板"、"示例"拆到references/，SKILL.md里只留流程和判断逻辑。

## 写作原则

### 1. 祈使句 > 被动句
- ❌ "冷静分析应该被调用来处理这个任务"
- ✅ "调用冷静分析，按配方A处理"

### 2. Why > Must
- ❌ "MUST use the template exactly"
- ✅ "用这个模板，因为读者期待一致的结构"

### 3. 带例子
- 每个输出格式给一个示例
- 有示例的skill比纯规则的skill效果高30%+

### 4. 避免过度约束
- 如果在写"MUST ALWAYS NEVER"，先想想能不能解释原因
- 过度约束导致agent僵化，不适应边界情况

## 常见模式

### 流程型技能
```
第一步 → 第二步 → 第三步 → 输出
```
适用：录音分析、合同审核、文档生成

### 判断型技能
```
输入 → 判断条件A？→ 是→路径1 / 否→路径2 → 输出
```
适用：分类、路由、决策

### 协作型技能
```
接收任务 → 判断谁来做 → 派发 → 收集结果 → 整合输出
```
适用：CEO调度、项目管理

### 对话型技能
```
开场 → 对话循环 → 深挖 → 判断是否结束 → 输出报告
```
适用：球球老师、咨询、教练
