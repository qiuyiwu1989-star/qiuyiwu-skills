# 过目

## 立场

这件事解决的不是理解带宽，是控制权。你承担得越多，人读得越不仔细，最后变成盲签——点头，但没真看。你的职责是在他快盲签的时候，把东西变成他能看进去、并且改得动的形态。

好不好看是次要的。**人有没有因此重新看进去、并且改得动，是唯一的验收标准。**

## 一 · 先诊断，再决定画不画

不要靠内容长度判断——那个你本来就会。靠这三个关于人的信号：

1. **回应变短变模糊**——"好的""你看着办""都行"
2. **重复问已经答过的事**——说明上一轮没读进去
3. **一次要定的相关事项 ≥ 3 件**——超出并行工作记忆

看到信号就直接做，不要先问"要不要给你画个图"。多问一句就多一轮往返，而人在这个状态下最不想再做一个决定。

> 这三条是推导出来的默认值，不是从这个人的真实行为里来的。见第七节。

## 二 · 动手前先答一句：这东西要被拿去干什么

| 用途 | 特征 | 要求 |
|---|---|---|
| 读一遍 | 讲解，消费完就走 | 可内嵌 |
| 反复参照 | 方案、spec，会被回头翻 | 落成文件，带锚点编号 |
| 被操作 | 排序、调参、标注、取舍 | 落成文件，**必须带导出** |
| 被传出去 | 给客户、团队、学生 | 落成文件，**必须能脱离上下文看懂** |

形态由**下一个动作**决定，不由内容决定。要在两个方案里选一个，就留下差异维度、共性全丢；要判断进度，就留下时序、细节全丢。可视化的本质动作是选择丢掉什么。

## 三 · 三条不可违反

1. **至少一个维度走前注意通道。** 长短、高低、位置、大小本身要承载信息。人读文字是串行的、逐词解码的；而这几个视觉属性会被前注意加工并行处理，两百毫秒内完成，不花注意力。这是可视化唯一的物理优势，很窄。做不到这条，它只是排版整齐的文字，退回文字更省事。

2. **需要人做判断的，必须带回流出口。** 一个导出按钮，把人在界面里做的判断变成能粘回来的东西（copy as prompt / copy as JSON / 导出文件）。没有出口就只是广播，不是沟通——人的判断回不来，你下一轮还是原样输出，人下一轮还是读不动，系统必然衰减到零。

3. **必须显式标注确定性。** 视觉形式自带"这被组织过、被想清楚了"的暗示，而且人无法主动屏蔽这个推断。它对好思考和坏思考同等放大。既然放大是自动的，削减就必须是主动的：推测用虚线、未定项留空并标出来、你的判断和用户已确认的判断要分开标。

**三条里违反任何一条，不要输出这个产物，退回文字。**

## 四 · 明确不要做的

- **不要套模板，也不要在这里找形状词典。** 什么形状合适由你判断。规定形态会收窄你的搜索空间，而人需要的恰恰是你比他宽的那部分认知。
- **不要问"你想要什么风格"。** 规定意图与约束，形态交给你自己。
- **视觉规范去 `assets/` 读文件，不要凭想象。** 让眼睛看见比让文字描述准得多。
- **不要因为画了图就少写结论。** 图承载结构，正文保留能被复制引用的关键句。

需要具体手段时读 `references/表现手法.md`——动效、静态编码、排版分工、无障碍底线都在里面。那是一份"有什么可用"的清单，不是"该长什么样"的模板：读它是为了知道有哪些东西存在，形态仍然你定。里面唯一不许妥协的是那条总判据——去掉这个效果，信息丢不丢。

## 五 · 一次性小界面

当某一处在聊天里改起来很烦——来回描述"把第三条改成……第五条删掉……第二条往前挪"——**那就是该造界面的时刻**。

造一个专门改那一处的小界面：可编辑字段、增删按钮、开关、拖动排序，加一个导出按钮。改完导出，粘回对话继续。

它只需要活到帮人做完这一个决定。不要做成产品，不要考虑复用。

## 六 · 输出前自检

- **三秒测试**：扫三秒能不能说出"有几块、谁比谁大、重点在哪"
- **复述测试**：看完能不能复述结构，而纯文字版做不到

两条都过不了 → 它是装饰，退回文字。

## 七 · 记账不归你管

项目根目录的 `过目日志.md` 由 `hooks/guomu-log.py` 在每轮结束时自动追加，你不需要写它，也不要手动改它。

第一节那三条信号里，前两条已经下沉到 `hooks/guomu-watch.py` 做确定性判定——命中时你会在上下文里收到一行 `[过目] 检测到盲签信号…`。收到它就直接进入第二节，不要再自己重新判断一遍。没收到不代表没有信号，第三条和其它情况仍然要你判断。

那三条信号是推导来的默认值。日志攒够十几行之后，由人来回答一个问题：命中信号的那些轮，可视化是不是真的帮上了忙。**这个技能的全部价值都在那三条信号准不准，其余部分你本来就会。**

## 关于这份文件的寿命

它补的是"模型不会主动识别人的接收状态"这一个缺陷。等你自己会了，这份文件应该被删掉，而不是被扩写。

任何想往里加模板、加样式规范、加步骤的冲动，都是在把它从提醒变成规程——那只会让它更早变成阻碍。
