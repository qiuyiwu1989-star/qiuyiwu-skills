## SKILL 定位
**核心判断**：用最低的复杂度解决问题，而不是用最高的复杂度展示技术能力。L2→L4成本增幅8-15倍，必须在每次架构决策中被明确量化。

## 五层速查

| 层级 | 名称 | 成本倍数 | 适用场景 | 当前状态 |
|------|------|---------|---------|---------|
| L1 | 单Agent+工具 | ×1 | 单步清晰任务 | 成熟 |
| L2 | 工作流型 | ×1.5-2 | 固定步骤，有限分支 | 成熟 |
| **L3** | **监督者编排** | **×3-5** | **动态规划，相对可控** | **当前生产最佳实践** |
| L4 | 群体协作Swarm | ×8-15 | 高度多样动态分工 | 谨慎 |
| L5 | 自组织群体 | 研究阶段 | 涌现式协同 | 极谨慎 |

## 决策树
1. 任务步骤固定且边界清晰 → L1/L2
2. 需要动态规划但流程相对可预期 → L3（优先）
3. 任务类型高度多样且动态分工 → L4（谨慎，先用L3验证）
4. 自发涌现式协同已在生产验证 → L5（极谨慎）

## 四步执行
**S1** 描述任务特征（步骤数/动态规划需求/任务多样性/复杂度容忍度）
**S2** 套用决策树，记录选择理由（不只是结论，还有「为什么L-1级不够」）
**S3** 评估L3→L4跃升成本价值比（如果考虑L4）
**S4** 配合可靠性目标，设计对应层级的容错机制

## 典型误区
- 追求L4/L5展示技术能力 → 层级是工具，不是荣誉
- 忽视8-15倍成本增幅 → 必须量化列入决策讨论
- 用高架构解决流程设计问题 → 先检查L3是否已能解决
