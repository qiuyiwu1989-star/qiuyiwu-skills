## SKILL 定位
**做什么**：分析Agent每个决策点的上下文需求，设计六层信息架构，建立质量追踪体系。
**核心判断**：Agent质量70%取决于上下文工程，而非模型本身。设计顺序：先定义上下文需求，再设计交互，最后确定提示词。

## 上下文六层速查

| 层次 | 内容 | 关键原则 |
|------|------|---------|
| L6 系统提示 | 角色/边界/格式 | 稳定层，精准定义，不含模糊指令 |
| L5 知识/记忆 | 长期记忆/RAG结果 | 只检索当前决策真正需要的内容 |
| L4 工具结果 | 外部调用结果 | 结构化JSON > 自然语言段落 |
| L3 任务上下文 | 当前任务背景 | 越完整越好，但不包含无关历史 |
| L2 用户输入 | 当前轮次输入 | 交互设计帮助用户提供高质量输入 |
| L1 输出约束 | 格式/长度/风格 | 在上下文设计阶段定义，非后处理 |

## 三个核心原则
1. **决策点优先**：先找决策点，再反推上下文需求
2. **精准 > 丰富**：上下文噪声是性能下降的主要原因
3. **结构 > 自然语言**：工具结果用JSON，不用文本段落

## 执行步骤
**S1** 决策点映射：识别所有Agent需要做判断的节点（含中间判断）
**S2** 上下文需求分析：对每个决策点，按六层分析需要什么信息，识别信息缺口
**S3** 工程实现：写入系统配置（提示词 + RAG策略 + 工具格式规范），执行上下文剪枝
**S4** 质量追踪：信息完整率 + 信息精准率 + 结构化率，月度追踪

## 典型误区
- 信息越多越好 → 噪声降低注意力质量
- 把提示词优化当上下文工程 → 提示词只是L6
- 上下文设计只是工程师的工作 → 需求分析必须由产品团队主导
