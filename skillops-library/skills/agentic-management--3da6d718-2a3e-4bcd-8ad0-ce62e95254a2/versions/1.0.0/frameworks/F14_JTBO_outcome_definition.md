## SKILL 定位
**做什么**：为Agent产品定义结果（而非任务）、建立所有权归属、重建KPI体系、评估结果定价可行性。
**核心判断**：工具帮你做事，Agent替你负责——评估锚点从「能否操作」转向「结果是否达标」。

## JTBO三层结构速查

| 层次 | 关键问题 | 常见错误 |
|------|---------|---------|
| 结果层（Outcome） | 什么叫事情搞定了？ | 把任务完成当结果达成 |
| 任务层（Job） | 用户委托了什么？ | 停留在任务描述，不追问结果 |
| 所有权层（Ownership） | 结果没达成，谁担责？ | 责任真空——没有具名负责人 |

## 结果定义四要素
```
① 结果描述（What）：具体可感知的状态变化（非动词开头的任务描述）
② 验证方式（How）：如何确认结果真的发生，而非看起来发生
③ 时间边界（When）：结果需要在什么时间窗口内达成
④ 所有权归属（Who）：具名的人或Agent角色，主动负责结果未达成的跟进
```

## 执行步骤
**S1** 识别真实结果：连续追问「然后呢」直到找到用户真正在意的状态变化
**S2** 所有权归属：为每个核心结果指定具名负责人，消除责任真空
**S3** 重建KPI：结果达成率（核心）+ 再次委托率（核心）；任务完成率（诊断指标）
**S4** 结果定价可行性：结果可清晰定义 + 可靠验证 + 对用户价值显著 → 考虑per-outcome定价

## 典型误区
- 把任务完成率当结果达成率 → 技术完成≠业务成功
- 忽视所有权层 → 结果没达成无人跟进是最大的治理盲区
- 创意类任务强行定义精确结果 → 导致指标失真
