## SKILL 定位
**核心判断**：CPTA不能单独使用——低CPTA不等于高价值。必须与结果价值配对解读。分母必须是业务语义成功率，而非技术完成率。

## 公式速查
```
CPTA = （Token成本 + 工具调用成本 + 基础设施成本 + 人工审校成本 + 构建成本摊销）
       ÷ （总请求数 × 业务语义成功率）
```

## 五项成本 + 最容易低估的是哪项

| 成本项 | 最常见低估原因 | 最高效优化手段 |
|--------|-------------|-------------|
| Token成本 | 不按任务类型分摊 | Prompt Caching（降50-90%）|
| **工具调用成本** | **RAG密集型中可能超过Token成本** | 缓存热点检索结果 |
| 基础设施成本 | 按月付固定费不分摊 | 右sizing + 按需伸缩 |
| 人工审校成本 | 忽略低频高时薪的专家介入 | 提升Agent可靠性减少介入 |
| **构建成本摊销** | **最常被遗漏** | 合理摊销周期（建议3-5年）|

## 分母的关键设计
**业务语义成功率** ≠ **技术完成率**
- 差距可能高达25%（技术完成但业务失败的任务）
- 用技术完成率会严重低估真实成本
- 成功定义需与业务团队共同确认（基于JTBO结果定义）

## 四步执行
**S1** 建立五项完整成本采集（特别确保工具调用和构建成本不遗漏）
**S2** 与业务团队共同定义成功率（最重要的一步）
**S3** 计算月度CPTA趋势（突然上升→先查工具调用成本和人工审校）
**S4** 与ROI配对使用（低CPTA+低价值=无商业意义；高CPTA+高价值=可能有正ROI）

## Token成本下降的战略含义
Token成本每年下降约10倍→今天CPTA偏高的场景，18-24个月后可能变得经济→需要动态追踪，不应因当前CPTA偏高就放弃有潜力的场景
