## SKILL 定位
**核心判断**：三层相互制约，任何单层极端优化都以损害其他两层为代价。追求三维平衡，而非单维最优。质量层最难建立但最关键——跳过质量层会导致「低成本快速地做了很多没价值的事」。

## 三层速查

| 层级 | 核心SLI | 典型SLO | 最容易犯的错误 |
|------|---------|---------|-------------|
| 质量层（顶） | 任务完成率/幻觉率/LLM-Judge评分 | 完成率≥92%，幻觉≤1.5% | 因为难测量就跳过 |
| 性能层（中） | TTFT/端到端延迟/超时率 | P95 TTFT<1.2s | 按任务类型分级（复杂任务需单独设SLO） |
| 成本层（底） | CPTA/缓存命中率/预算烧穿率 | CPTA≤$0.08，缓存命中≥40% | 只看总账单不按任务分摊 |

## Error Budget机制
- SLO = 92% → Error Budget = 8%（允许失败的月度空间）
- 消耗>50% → 警告：提高优化优先级
- 消耗>80% → 紧急：停止新功能开发
- 消耗100% → 冻结：禁止可能影响该指标的发布

## 四步执行
**S1** 建立三层监控基础设施（先从成本层开始，最易实现且价值最直接）
**S2** 设定初始SLO阈值（无历史数据→宽松阈值运行4-8周再收紧）
**S3** 建立Error Budget机制（SLO从看板变为运营决策工具的关键）
**S4** 月度三层综合复盘（用三角平衡视角：某层改善是否以牺牲其他层为代价）

## 典型误区
- 只追踪性能层 → Agent可以响应快但质量差
- 质量层LLM-as-Judge不校准 → 质量数字虚高
- 把系统可用性当Agent运营主指标 → 100%可用≠质量好
