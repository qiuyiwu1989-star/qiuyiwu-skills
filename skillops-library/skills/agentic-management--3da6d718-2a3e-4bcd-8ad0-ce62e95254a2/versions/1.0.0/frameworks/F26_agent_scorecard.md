## SKILL 定位
**核心判断**：Scorecard最重要的是「结果指标（40%）优先」的权重设计——Agent存在的根本价值是是否真正完成了有价值的结果，而非流程是否正确执行。两者经常不一致。

## 四维权重速查

| 维度 | 权重 | 核心指标 | 为什么这个权重 |
|------|------|---------|------------|
| 结果指标 | **40%** | 任务完成率/首次通过率/升级率/CSAT | JTBO核心理念落实，最重要 |
| 质量指标 | 25% | 准确性/相关性/完整性/安全性 | 可持续运营的信任基础 |
| 效率指标 | 20% | P95延迟/吞吐量/工具调用效率 | 决定规模化潜力 |
| 经济指标 | 15% | CPTA/ROI/缓存命中率 | 最低但最容易被完全忽视 |

## Agent与人类员工考核的三个关键差异
1. **无态度/潜力维度**：完全基于可量化行为结果
2. **改进周期压缩**：从月/季度→天/周（快速迭代）
3. **版本状态≠个体状态**：绩效下滑先查版本变更记录

## Agent Manager KPI（评估管理者，非Agent本身）
Portfolio健康度 / 平均故障恢复时间MTTR / 月度改进速率 / 年化ROI

## 四步执行
**S1** 建立四维指标采集（质量层最难，不能因为困难就省略）
**S2** 设定各维度SLO基线（结果指标SLO最先设定）
**S3** 建立月度Scorecard报告（综合评分 = 各维度得分×权重）
**S4** Scorecard与优化决策绑定（某维度<60%立即触发专项优化）

## 典型误区
- Scorecard只报告不绑定决策 → 退化为形式工具
- 结果指标权重设置过低 → 违背JTBO核心理念
- Agent Scorecard和Agent Manager KPI混淆 → 前者评Agent，后者评管理者
