# 智能体管理学 · 框架体系

> **来源**：诸葛（略懂AI）的完整方法论体系，原存于 `/opt/openclaw-luedong`，2026-11-14 抢救归档并打包为技能。
> **规模**：6 大模块 × 33 个框架 + 2 个横切治理神经。

## 使用原则

**这不是"知识库"，是"决策工具"。** 每个框架都带：
- **触发条件**（什么处境下用它）
- **核心判断**（一句话结论，反常识的居多）
- **执行步骤**（S1/S2/S3...）
- **常见错误**（最容易踩的坑）

**正确用法**：
1. 先判断用户处境属于哪个模块（见下方路由表）
2. 读取对应框架文件
3. **按框架的判断标准给结论，不要给通用建议**

## 模块路由表

### 模块一 · 战略定位（F01-F06）
**用于**：决定做不做、做哪个、凭什么赢

| 编号 | 框架 | 核心判断 |
|---|---|---|
| F01 | 智能体竞争分析（波特五力重写） | 竞争结构在 AI 时代已改变，传统五力不适用 |
| F02 | 七维护城河评估 | 护城河要量化——在加厚还是侵蚀 |
| F03 | Agent 组合矩阵 | 自主化成熟度 × 战略价值，决定扩张/投入/控制/退出 |
| F04 | 3B 能力获取 | Build / Buy / Borrow 的选择标准 |
| F05 | AaaA 数字劳动力资产 | Agent 是资产不是工具，会计与估值逻辑要变 |
| F06 | AaaS 商业模式 | Agent 即服务的定价与交付结构 |

### 模块二 · 组织设计（F07-F12）
**用于**：怎么摆人、怎么摆 Agent、边界在哪

| 编号 | 框架 | 核心判断 |
|---|---|---|
| F07 | 智能体网络设计 | 人机混合组织的拓扑选择 |
| F08 | Agent 平台架构 | 中台该做什么、不该做什么 |
| F09 | 人机治理 | 决策权如何在人与 Agent 间分配 |
| F10 | 角色体系重设计 | 岗位不是被替代，是被重组 |
| F11 | 边界·升级·恢复 | Agent 失控时谁接、怎么接、怎么恢复 |
| F12 | 智能体转型跨越 | 转型进展诊断与跳变点识别 |

### 模块三 · 产品定义（F13-F18）
**用于**：这个 Agent 到底该长什么样

| 编号 | 框架 | 核心判断 |
|---|---|---|
| F13 | APS 定位 | **定位错误导致交互/定价/合规系统性偏差** |
| F14 | JTBO 成果定义 | **工具帮你做事，Agent 替你负责**——评估锚点转移 |
| F15 | 上下文优先设计 | **质量 70% 取决于上下文工程，而非模型** |
| F16 | 可靠性 PMF | **不是"用户喜不喜欢"，而是"用户敢不敢托付"** |
| F17 | VERITAS 评估 | 任何单维度低于阈值即构成上线风险 |
| F18 | CATER 治理信任 | **治理信任 ≠ 能力信任** |

### 模块四 · 工程实现（F19-F23）
**用于**：怎么把它造出来

| 编号 | 框架 | 核心判断 |
|---|---|---|
| F19 | MAS 架构选型 | **用最低复杂度解决，不是用最高复杂度** |
| F20 | 3E 工程 | **谁把 Evals 做深，谁就赢得竞争** |
| F21 | Skill 资产治理 | 从「文档管理」到「能力资产管理」的跃迁 |
| F22 | 上下文工程落地 | 升级模型后 Prompt 性能下降，是最常见的隐性事故 |
| F23 | AEA 企业架构 | 协议层（MCP+A2A）是未来十年最重要的战略投资 |

### 模块五 · 度量与成本（F24-F28）
**用于**：怎么证明它有用、花了多少钱

| 编号 | 框架 | 核心判断 |
|---|---|---|
| F24 | PRT 概率回归测试 | 传统单测在 Agent 系统产生两种致命错误 |
| F25 | 三层 SLO 金字塔 | 三层相互制约，单层极端优化必损其他层 |
| F26 | Agent Scorecard | **结果指标（40%）优先于过程指标** |
| F27 | CPTA 成本计算 | **低 CPTA ≠ 高价值**，必须配合 F28 |
| F28 | Agent ROI | **0-6 个月负 ROI 是正常的**，「3 个月不见效就放弃」常发生在跨越盈亏点前 |

### 模块六 · 人与风险（F29-F33）
**用于**：人怎么办、风险怎么控

| 编号 | 框架 | 核心判断 |
|---|---|---|
| F29 | Agent 风险治理 | 提示注入是当前最活跃攻击面 |
| F31 | 角色转型地图 | **AI 改变的是任务，不是岗位** |
| F32 | Agent 素养评估 | 核心不是「会用多少工具」，而是「能不能判断何时不该用」 |
| F33 | AC6 核心能力（收官） | **AI 普及不会让人的价值趋同，而是加速分化** |

### 横切治理神经
| 编号 | 名称 | 作用 |
|---|---|---|
| 神经① | 意图管理模型 | 跨模块激活，用于意图对齐 |
| 神经③ | 智能体主权模型 | 横切全体系，用于主权边界判定 |

## 典型使用场景

**场景 1：老板问"我们投了这么多 AI，到底值不值"**
→ F27（CPTA 算成本）+ F28（ROI 算回报）+ F26（Scorecard 定指标）
→ **关键提醒**：0-6 个月负 ROI 正常，别急着砍

**场景 2："我们要不要做 Agent 中台"**
→ F08（平台架构）+ F19（架构选型）+ F23（协议层）
→ **关键提醒**：用最低复杂度解决，别一上来就做中台

**场景 3："这个 Agent 能不能上线"**
→ F17（VERITAS 六维）+ F24（PRT 测试）+ F29（风险治理）
→ **关键提醒**：任何单维度低于阈值就是风险

**场景 4："AI 来了，我们岗位怎么调"**
→ F31（角色转型地图）+ F10（角色体系）+ F32（素养评估）
→ **关键提醒**：改的是任务不是岗位，别急着裁人

**场景 5："怎么向董事会证明 AI 战略"**
→ F28（ROI 时间曲线）+ F02（护城河）+ F03（组合矩阵）
→ **关键提醒**：必须给时间曲线，不能只给单点数字
