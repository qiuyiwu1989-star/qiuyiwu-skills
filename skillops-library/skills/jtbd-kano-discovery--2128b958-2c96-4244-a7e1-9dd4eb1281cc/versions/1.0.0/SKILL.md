# JTBD × KANO 需求挖掘与排序

## 方法总览：挖 → 筛 → 排 → 验

```
① JTBD 挖掘          ② 痛点强度初筛         ③ KANO 分类排序          ④ 概念验证
场景/访谈/录音  →  Job 清单(10-30条)  →  每条打"拿走会难受吗" →  问卷或专家推演  →  Top3-5 做成海报/
                    功能/情感/社会三层       频率×强度×付费意愿      Better-Worse 矩阵      概念视频，让用户选
```

核心判断标准（来自会议共识）：**雪中送炭 > 锦上添花**。"没有它会觉得难受"的才是痛点；"有了更好、没有也行"的放到后面做惊喜。

## 阶段 ① JTBD 挖掘

目标：回答"用户在什么情境下，想取得什么进展"，而不是"用户想要什么功能"。

1. **划定角色**：列出所有相关角色（使用者、付费者、决策者、受影响者）。例：孩子、家长、祖辈/育儿嫂、老师、校长。每个角色单独挖。
2. **找转折时刻**：对每个角色问"什么时候他的生活/工作突然发生变化，原有方式失效？"（入托、换老师、评价改革、骨干离职……）。
3. **写 Job Story**（标准句式，必须遵守）：
   > **当** {具体情境/触发时刻}，**我想** {要取得的进展}，**以便** {期望结果}。
4. **三层展开**：每个核心 Job 再拆
   - 功能性 Job：要完成的事（知道孩子今天发生了什么）
   - 情感性 Job：想要的感受（不再焦虑、觉得自己是好家长）
   - 社会性 Job：想在他人眼中的形象（在家人/老师面前有依据）
5. **找"雇佣与解雇"**：用户现在"雇佣"了什么方案完成这个 Job（问孩子、问老师、看监控、钉钉录音），为什么不满意 → 不满意处即机会。
6. **挖掘四种力**（判断用户会不会真的换）：现状之推（痛）、新方案之拉（吸引）、习惯之阻、焦虑之阻（隐私、被监控、价格）。

详细提问清单与 Job 挖掘提示词见 `references/jtbd-guide.md`。

**从会议录音/访谈稿挖掘时**：逐段扫描"抱怨、焦虑、绕路方案、'要是能……就好了'、举例的真实故事"，每处标注发言人与原话，转写成 Job Story。

## 阶段 ② 痛点强度初筛

对每条 Job 快速打分（1–5），淘汰总分过低者，保留 8–15 条进入 KANO：
- **频率**：多久遇到一次
- **强度**：发生时有多难受（"拿走会难受吗？"）
- **现有方案不满度**
- **付费意愿/预算归属**：谁出钱、钱从哪个预算出

## 阶段 ③ KANO 分类与排序

两种执行方式，按是否有真实用户数据选择：

**A. 有用户可调研 → KANO 问卷（首选）**
1. 用 `assets/kano-questionnaire-template.md` 为每条需求生成正反向问题对（"如果有 X，你觉得？/ 如果没有 X，你觉得？"，五级选项）。
2. 回收后整理成 CSV（格式见模板），运行：
   ```bash
   python3 scripts/kano_score.py responses.csv -o kano_result.md
   ```
   脚本输出：每条需求的 KANO 类别分布、主类别、Better/Worse 系数、象限与建议优先级（markdown 表格）。
3. 样本量：每个细分人群 ≥15 份才有参考意义；少于此标注"仅供参考"。

**B. 暂无用户数据 → 专家推演（快速版）**
对每条需求逐一回答"有它时用户的反应 / 没它时用户的反应"，按 KANO 评价表判类，并说明依据；明确标注"推演结果，待问卷验证"。

**KANO 类别与动作**
| 类别 | 含义 | 动作 |
|---|---|---|
| M 必备型 | 没有就不满，有了也不加分 | 必须做，作为门槛，不宜作宣传主线 |
| O 期望型 | 越好越满意，没有就不满 | 优先做，**叙事主线首选**（雪中送炭） |
| A 兴奋型 | 有了惊喜，没有也无所谓 | 选 1–2 个做差异化惊喜（锦上添花） |
| I 无差异 | 有无都无所谓 | 砍掉 |
| R 反向 | 有了反而不满 | 不做，或做成可关闭（如"被监控感"） |

**排序规则**：M（未满足的）> O（按 Better 降序）> A（按 Better 降序，取前 1–2）> I；R 单列为风险。再与阶段②的付费意愿交叉，得到最终 Top 3–5。
Better-Worse 系数与四象限解读见 `references/kano-guide.md`。

## 阶段 ④ 概念验证（低成本）

将 Top 3–5 需求各做成一张**需求海报**或一段 **15–30 秒概念视频**（可调用 ImageGen / VideoGen），发给目标用户："你最想要哪一个？愿意为哪个付钱？"——以用户选择修正排序，再投入开发。
海报/视频文案按 `user-value-storytelling` skill 的"场—痛—解"写，不写功能清单。

## 输出格式

使用 `assets/discovery-report-template.md` 输出报告，必须包含：
1. 角色地图
2. Job Story 清单（含原话出处）
3. 初筛打分表
4. KANO 分类表 + 优先级 Top 3–5（标明问卷或推演）
5. 风险项（R 型与"焦虑之阻"）
6. 概念验证计划（海报/视频标题与一句话文案）
7. 下一步：种子用户招募建议
