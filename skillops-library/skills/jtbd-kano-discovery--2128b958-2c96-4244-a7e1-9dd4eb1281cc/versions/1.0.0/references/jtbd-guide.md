# JTBD 实操指南

## 1. 核心理念
用户不是"买产品"，而是"雇佣"产品来完成某项任务（Job）以取得进展。Job 稳定、与方案无关；方案会被更好的方案替代。
- 错误：用户需要"一个录音胸牌"
- 正确：当孩子刚离开我的视线进入新环境时，我想知道他是否安好、经历了什么，以便我晚上能正确地陪伴他

## 2. 访谈提问清单（按时间线还原一次真实经历）
1. **第一念头**："你最早是什么时候觉得这件事需要解决？当时发生了什么？"
2. **被动寻找**："那之后你注意到/听说过哪些办法？"
3. **主动寻找**："你实际试过什么？花了多少时间/钱？"
4. **决策**："最后为什么选了它/放弃了？谁参与了决定？"
5. **使用后**："用了之后哪里比预期好/差？现在还在用吗？"
6. **假设拿走**："如果明天这个办法没了，你会怎么样？"（检验雪中送炭）
7. **理想结果**："如果完全解决了，你的一天会有什么不同？"

**规则**：问过去的具体事件，不问未来的假设偏好（"你会买吗？"无效）；追问"为什么"直到触及情感/社会层面。

## 3. 四种力（判断用户是否真的会切换）
| 力 | 问题 | 例（家长线） |
|---|---|---|
| 推力（现状之痛） | 现在哪里难受？ | 孩子哭了三次不知原因 |
| 拉力（新方案吸引） | 新方案哪点吸引他？ | 每晚知道孩子发生的 3 件事 + 陪伴建议 |
| 习惯阻力 | 现在的做法有什么让他不想换？ | 习惯问老师、看家长群照片 |
| 焦虑阻力 | 换了会担心什么？ | 学校禁止、隐私、孩子被另眼看待、录到别人 |
推力 + 拉力 > 两种阻力，才会行动。焦虑阻力要写进产品设计与叙事的"顾虑预案"。

## 4. 从会议录音/访谈稿中挖掘（AI 执行步骤）
逐段扫描以下信号，摘录"发言人 + 原话 + 时间戳"：
- 抱怨与焦虑词："不知道""担心""很痛""好难""烦"
- 绕路方案："我只能……""我们现在是先……再……"
- 愿望句："要是能……就好了""能不能……"
- 真实故事：带具体人物与经过的案例（最有价值）
- 预算与付费信号："花了 3 万多""有预算""愿意每月……"
然后把每条信号转成 Job Story，合并同类，标注角色。

## 5. 让 AI 挖掘的提示词
> 用 JTBD 方法，基于以下材料，为【角色列表】分别挖掘所有潜在的 Job。每个 Job 用"当……我想……以便……"句式，拆分功能/情感/社会三层，列出用户当前"雇佣"的替代方案及其不足，标注材料中的原话出处。尽量穷举，至少 15 条，然后合并去重。

## 6. Job 质量自检
- 是否包含具体触发情境（而非"日常"）？
- "我想"部分是否不含任何具体产品/功能？
- "以便"是否指向可感知的结果？
- 能否找到至少一个真实用户故事支撑？
