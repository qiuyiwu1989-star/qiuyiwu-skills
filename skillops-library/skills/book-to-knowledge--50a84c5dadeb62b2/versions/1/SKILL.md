# 书库：读过的书，成为可阅读、可调用的记忆

主要交付是人能连续阅读的页面，兼具对外展示与 AI 孪生的上下文价值。用户只需输入书名；在明确的“已读且值得留存”入口记录 read / retained，通用入口不猜阅读状态。留存不等于认同全部观点。不要求个人说明，不制造第一人称读后感或人生经历。

## 不变量

- 页面先呈现不编号的书籍元信息；正文五部分为：**一、全书概述；二、真问题；三、知识地图；四、核心模型深度解析；五、深度洞察摘录**。页尾资料说明。行动清单、费曼检验、个人实践不是固定章节。
- 内容适配书，不强迫书适配模板。没有模型的文学作品，用核心命题、叙事结构或观察承担第四部分，页内副标题解释适配。不能给小说发明管理模型。
- 原书陈述、他人解释、AI 推断、用户判断分别归属。公开材料不是原书全文；作者后续观点不是自动属于早期版本。
- 页面、Markdown 与 JSON 从同一内容对象渲染；每条展示性解释、案例、边界和洞察均须在数据中有归属与定位。不能只把标题与一句话存入库，再在 HTML 另写一篇。
- 使用已有 book_id。重复录入先查，更新不重复建书；命题变更保留修订。书、版本、阅读状态与认同分别存储。

## 作业流程

1. **辨认与取材。** 查现有书目、BookPress 报告、原文及可信公开资料，确认作者与版本范围。书名歧义真正影响内容时才提问，其他缺项留空并继续。不要通过导入带迁移副作用的数据库模块做只读查询。
2. **建立内容骨架。** 先读 [内容标准](references/content-standard.md)。列出本书的主问题、核心回答、主要论证与证据，并标记覆盖缺口，再写长文。地图首先描述思想结构，不优先写成执行步骤。
3. **生成同源档案。** 按 [数据与来源契约](references/contract.md) 保存五部分及知识原子，原子之间有可解释关系。先写内容，再赋予页面样式，不在 HTML 临时补写独有正文。旧报告抽取与新增公开资料综合须分开标记。
4. **编辑与反读。** 按 [质检与批次规则](references/quality.md) 做语义审核；从一个陌生读者的问题出发，检查问题、论证、案例、洞察能否互相支持。检查是否把其他书/新版/后续理论写进了本书。
5. **生成页面。** 按 [阅读设计](references/reading-design.md) 使用 qiuyiwu.com 设计系统。正文宋体，局部加粗，全文展开。页面没有空白个人感悟模块，也没有原始 JSON 大段展示。书库 route 保持 `/vault/books/`。
6. **验收与发布。** 运行 `python3 scripts/validate_pack.py <知识包目录>`，再做内容审核与实际浏览器验证。机械通过不证明内容正确。生成 `review.json`，写明可发布范围与未解决项。已有明确发布授权按范围自动执行，不要求用户逐书确认；没有时交付可审查结果，不擅自上传或生产写库。

## 材料不足时

仍生成有实际阅读价值的页面草稿，而不是只有空书目。只能依赖模型知识的部分写成 AI 暂定解读，不假造引文、章节、数据与案例。自动公开的内容必须满足 quality.md 的发布关口；缺证据不能用降低标准换取“上架成功”。两轮定向补材/修订仍不能解决实质缺口时，标 needs_materials 并继续批次中独立可做的书，保留失败原因，不无限重试。

## 文件与范围

默认 `knowledge/books/<book-id>/`：`book.json`、`index.html`、`report.md`、`manifest.json`、`review.json`。现有项目已有数据表/接口则做适配，不创建独立生产库。定义 skill 不等于线上工作流已集成。

本 skill 的内容标准为 `bookshelf-content/v2.0`，沿用 `book-knowledge/v1` 包格式并增加显式字段；旧样本须评估再迁移，不能只改版本号冒充合格。不自动重写已发布书籍或开始批量部署。

公开呈现规则：内部取材范围、核验过程、缺口、未提供个人笔记等信息保存在后台数据与审查记录，不直接写成面向读者的说明段落。页面聚焦书籍思想，页尾仅保留参考资料链接。此呈现规则优先于参考文件中要求向读者展示制作范围的旧措辞；不改变内容忠实性、来源保存或发布验收要求。

## 相关阅读

单书页尾使用相关阅读卡片，按 [推荐规则](references/recommendations.md) 从当前书库计算，不固定书名。生成/更新书籍后重建推荐索引并重算相关页面；构建时重算不能表述成在线个性化算法已上线。
