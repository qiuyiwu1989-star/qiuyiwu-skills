# Speech Recap · 演讲逐字稿成文（客观实录）

把一场讲完的演讲/课，整理成一篇**忠实、客观、可读**的图文实录，挂到 qiuyiwu.com 的演讲板块（`/<slug>/`）。

参考成品：`yuquan/index.html`（最干净的图文实录模板）、`tianyuan/article.html`。
**改这个 skill 前先读这两份**，模板以它们为准。

---

## 0. 定位（最重要，先读）

这是**记录**，不是营销稿。每一处取舍都向「真实、客观、好读」对齐，不向「传播、爆款」对齐。

**要做的**
- 把讲者真正讲的**核心价值点**提炼、归拢成清晰的结构。
- **修口误**：去掉「嗯/那个/是吧/这个」，补断句，纠正明显的口误与错字（如把口误的人名、年份、术语改对）。
- **顺逻辑**：把口语里跳跃、倒装、重复的地方理顺，让因果和递进读起来顺。
- **回归真实**：保留讲者第一人称口吻和他真实的措辞、故事、例子——这些是不可替代的部分。
- 锦上添花：如果有更准确的背景/事实细节能补全，可以补一句，但**不喧宾夺主**。

**不要做的（硬约束）**
- ❌ 不做钩子党标题、不强行把小标题写成金句。标题与小标题要**朴实、准确地概括内容**。
- ❌ 不替讲者拔高、不添加他没表达过的观点或结论。
- ❌ 不夸张、不煽情、不堆排比。情绪强度跟着讲者本人走。
- ❌ 不杜撰细节、数据、案例。补充内容必须是可核实的事实澄清。
- ❌ 金句可以保留（加粗或 `.pull`），但**克制**——是因为他确实讲到了，不是为了传播去制造。

判断基准：读者读完，应该感觉「这就是他讲的，只是更清楚了」，而不是「这被人重新包装过」。

---

## 1. 输入

- **逐字稿**：录音转写的 `.md`/`.txt`（通常带「说话人 N / 时间戳」，以讲者那一位为主线）。
- **PPT**：`.pdf`（讲者的课件，16:9）。
- **现场照（可选）**：有就给目录；**没有就先全用 PPT 渲染页**，后续有照片再补。
- **每场配置**（开工前问全，见 §6）：slug、标题、副标题、单位/场合、日期、受众、accent 色、脱敏/弱化清单、是否纳入 PPT 库及是否对外。

---

## 2. 流程（七步）

### Step 1 · 解析课件（PPT → 图 + 章节地图）
用 PyMuPDF（`fitz`）+ Pillow：
1. 逐页渲染成中高清 JPG（约 1600 宽）到暂存区；再拼成几张「拼图」(montage，每张约 14 页、2 列、标注页码)。
2. 抽每页可读文字（`page.get_text()`）；注意**自定义字体会出乱码**，乱码页就靠看图。
3. **读拼图**，把每一页映射成 `页码 → 主题`，并据此分出文章的章节段。
> 渲染脚本范式见 §7。

### Step 2 · 解析逐字稿（提炼脊与价值点）
通读全文，产出一份「整理笔记」：
- **结构脊**：讲者真实的讲述顺序（通常是「企业现实 → 一线观察/实验 → 宏观趋势 → 给听众的建议」，但以这次实际为准）。
- **核心价值点清单**：每一节他真正想说的 1-3 句要点。
- **金句/真实细节**：值得原样保留的原话、故事、例子（脱敏前先标出来）。
- **口误/重复/填充**清单：要修的地方。
- **脱敏项**：真名、企业、未成年人、场合性弱化项。

### Step 3 · 对齐大纲（逐字稿脊 × PPT 页序）
把「逐字稿的脊」和「PPT 的页序」对齐，列出分节大纲：
每节 = `小标题（朴实概括） + 对应 PPT 页 + 核心价值点 + 要保留的关键原话`。
这一步是把「他讲的」和「他放的」缝到一起。

### Step 4 · 成文（套固定模板，客观删订）
按 §8 的模板写。逐节把口语转成书面：修口误、去填充、顺逻辑，但**保真口吻**。
- 标题：朴实概括全场主题（不做钩子）。
- 小标题（h3）：准确概括该节内容；可选前缀 kicker 小词（如「案例 / 实验 / 数据 / 建议」）做节奏，但**不当金句用**。
- 每节按需配 1-2 张 PPT 渲染图（`figure` + `figcaption`，caption 客观描述该页）。
- 金句用加粗；整场最值得停顿的少数几句可用 `.pull`，克制。

### Step 5 · 配图与落地
1. 选定要进正文的页（封面 + 关键页；有现场照则交替插入），渲染成 webp（约 1100 宽）到 `/<slug>/fig/`、现场照 `fig/scene-*.webp`。

   **文件名必须是 `<deck>-<页码>.webp`（如 `gji-018.webp`），不要用 `pNN.webp`。**

   这不是风格偏好，是一条数据链路：文件名里的 deck-page 就是「这一节配了哪套课件的哪一页」，
   等于你在出稿时顺手标了一条**真值**。下游靠它把实录和 PPT 原子页对上，从而回答
   「这一页我讲过几场」——那个信号又反过来决定哪些页值得重制、备课时该优先取哪页。
   `pNN` 只记了"正文第几张图"，出处当场丢失，**事后无法恢复**。

   实况（2026-08-11 全站盘点）：87 张配图分布在 14 篇实录已经是 deck-page 式，
   只有 tianyuan / yuquan 两篇共 51 张是旧的 `pNN` 式。好做法已经赢了，这里只是把它写成规范。
   那两篇如果哪天重制，顺手改名即可。
2. 写 `/<slug>/article.html`（或按惯例 `index.html`），补 SEO meta + `Article` JSON-LD（canonical、og、datePublished、author=邱懿武、publisher=造物云）。
3. 若该 slug 已有「落地页」（如 tianyuan 的两段式），把文章入口接上。

### Step 6 · 脱敏与弱化
- **固定**：合作企业一律匿名/脱敏（「一家家电集团」「某百年供应链龙头」）；未成年人隐去可识别信息。
- **场合性弱化项**（每场可配）：按清单淡化特定表述（例：某场要「弱化浙大返聘」就把相关自述改低调）。
- 全文 grep 真名/企业名/未成年人姓名，确认 0 残留；核对口误清单是否都修了。

### Step 7 · 验收
- 本地 http-server + curl/预览：页面 200、配图全部解析、SEO/JSON-LD 在。
- 给邱懿武看（URL/截图）。按反馈微调。
- 部署走仓库的 GitHub Action（push 到 main 自动上线，见仓库 DEPLOY-OWNERSHIP.md）；**push 前确认**。

## 3. 可选：纳入原子 PPT 库
若配置要「纳入 `/slides.html`」：把 80 页（或 N 页）作为新 deck 写进 `data/slide-library.json`（`decks` + `slides` + `atoms`，逐页 title/keywords/section，缩略图 266×150 存 `uploads/slides/<code>-NNN.jpg`），更新计数；**先备份 json**。
若配置「不对外」：不写入公开库，或写入后从公开数据撤下（注意 GitHub Action 主站 rsync 不带 `--delete`，撤图需手动在服务器删）。

## 4. 风格 DNA 速查（写每一句时回看）
- 第一人称、讲者真实口吻；书面但不端着。
- 标题/小标题：准确 > 抓人。
- 删订三件事：去填充词、顺逻辑、纠口误。其余尽量留原话。
- 不添观点、不拔高、不煽情、不杜撰。
- 金句克制；`.pull` 一节最多一句、整篇几句。
- 配图 caption 客观陈述该页内容，不喊口号。
- **标点**：中文引号一律用弯引号 `“”`，**不用直角引号 `「」`**。成文后 grep `「`/`」` 确认 0 残留。

## 5. 反面例子（来自一次复盘）
- ❌ 标题《别把孩子，养成毕业那天就被 AI 替代的人》——太「传播」。
- ✅ 标题《AI 原生教育的思考与探索》/《还在商业化中的 AI，从学校到产业》——朴实概括。
- ❌ 小标题《年轻人从菜鸟到专家的那座桥，断了》——金句化。
- ✅ 小标题《菜鸟危机：实习生、练习生的岗位在消失》——客观概括。
（注：标题钩不钩人是风格选择；本 skill 一律选客观那一侧。）

## 7. 渲染脚本范式（PyMuPDF）
```python
# DECK = 这套课件在 data/slide-library.json 里的三字母 code(mba/k12/gji/mgt/pdf/obj…)。
# 新课件还没进库就先起一个,入库时对齐。文件名带上它,出处才留得住(见 Step 5)。
DECK = "gji"
import fitz, io
from PIL import Image
doc = fitz.open(PDF)
for i in range(doc.page_count):
    pix = doc[i].get_pixmap(matrix=fitz.Matrix(1100/1920, 1100/1920), alpha=False)
    img = Image.open(io.BytesIO(pix.tobytes("ppm"))).convert("RGB")
    # 文件名带 deck code + 原页码 —— 出处即真值,见 Step 5。不要写成 p01.webp。
    img.save(f"<slug>/fig/{DECK}-{i+1:03d}.webp", "WEBP", quality=80)   # 正文配图
# 库缩略图 266x150 → uploads/slides/<code>-NNN.jpg, quality~82
# 拼图：每 14 页拼一张、2 列、标页码，供「读图映射章节」
```
注意：>100MB 的 PDF，Read 工具读不了，必须用 fitz；文字层可能是自定义字体乱码，乱码页靠看渲染图。

## 8. 文章模板（结构以 yuquan/index.html 为准）
自包含单页 HTML，不依赖站点 styles.css。骨架：
- `:root` 配色（`--accent` 按场配）；浅/深色各一套。
- `.topbar`（品牌 + 站点链接）。
- `header.hero`：`.eyebrow`(演讲整理 · 场合) → `h1`(朴实标题) → `.sub`(副标) → `.meta`(邱懿武 · 日期 · 场合 · 受众) → `.lead`(一段客观导语：这是哪场分享、整理成文、讲了什么脊)。
- 封面 `figure`（PPT 第 1 页）+ 可选现场照。
- `article`：用 `.part`/`.part-tag` 分大段；`h3`（可带 `.pg` kicker）开小节；`p`（`.hl` 高亮、`b` 加粗）；`.pull` 金句块；`figure`+`figcaption` 配图。
- `.endnote`：一句「现场分享文字整理版，企业匿名、未成年人脱敏」+ 版权。
- `footer.foot`。
完整 CSS 直接复用 yuquan/tianyuan 的 `<style>` 块，只换 `--accent` 与文案。
