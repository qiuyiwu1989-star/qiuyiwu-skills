# 阅读档案交付审核 v1.0

用途：审核一份真实交付，不给模板打“内容合格”分。先读quality-standard.md。内容、结构、页面分别记录状态，排版通过不代表内容通过。

## A 内容证据审核（必须对照实际材料）

| 检查项 | 通过依据 | 阻断问题 |
|---|---|---|
| 来源与范围 | 记录实际读取材料、全文/节选/编译及未核实处 | 未取得正文却声称完整；未核听却声称核实 |
| 主线与概述 | 概述的主要判断在正文与来源有支撑 | 标题/导读放大断言；概述引入来源没有的结论 |
| 主题覆盖 | 覆盖表对应主要判断、转折、例子和边界 | 完整提炼漏关键主题；选编冒充完整 |
| 推理与案例 | 读者能理解为什么，案例支持哪个判断 | 只有结论清单；删除决定结论的限定 |
| 数字与引语 | 单位、时间、口径、主体、预测性质保留 | 数字错配；预测写事实；编译转述冒充核实原话 |
| 归属与增量 | 来源表达、整理者分析、用户判断分开 | AI推断写成用户立场；无依据强拉用户项目 |

不能用“保留80%价值”“字数足够”“有十个章节”证明通过。无来源支持时收窄或标为待补充，不补造。

## B 结构与字段审核

每篇唯一标题和导读；有全篇概述，主线与正文一致；日期不混用；作者/讲者/机构角色与材料匹配；来源链接可辨且可追溯；缺失项省略/说明，不伪造；元数据与页面一致；无重复后台字段清单；分析归属明确；材料附录有实际内容及允许展示的范围。多来源有分歧时分别归属。页面与JSON由同一次修订生成。

## C 页面与交互审核

沿用V3及共享阅读组件；正文宋体、h2加粗；桌面1440、手机390/320，深浅主题无整页横向溢出；长表格局部滚动；目录标签完整且编号对齐，当前章高亮唯一，点击标题不被导航遮挡，手机选后收起；初始hash/键盘焦点可用；来源链接和引用有效；字体加载失败仍可读。无JS正文仍可阅读。不能仅靠HTML有效或截图好看来判内容合格。

## 判定与交付记录

逐项记录“通过／待补充／不适用”，附来源位置、页面选择器或核对事实；不适用须给原因。存在A类实质错误或B类身份/来源/日期错误时不得称可发布；修正后再核对受影响内容。C类会影响阅读、导航或来源访问的缺陷先修复。没有执行的检查写“未验证”，不能打通过。

交付给用户的一句话应明确：内容审阅范围、页面验证范围、实际发布状态、剩余缺口。内部保留简短审核表，不把审核清单整块塞进阅读页。Agent自审不等于用户认可，清单也不自动赋予发布权限。

记录格式：
- 来源/范围：……
- 内容：通过/待补充；依据……
- 字段与归属：通过/待补充；依据……
- 页面：通过/未验证；宽度/主题/交互……
- 状态：本地稿/已提交/已上线；关键缺口……
