# 从结论摘录到提炼：合成对照

以下完全虚构，仅说明写作方法；不是访谈事实或实际客户资料。

## 合成原材料

一位虚构产品经理讨论试点：团队把原来的人工逐条检查改为机器排序，再让人复核。一次假想测试中，总处理时间减少，但复核者指出重要事项更容易被漏看。团队因此决定不以总耗时作为唯一指标，补查关键事项的漏检情况，并在扩大试点前先调整排序。访谈没有给出完整样本规模。

## 不足的写法

“产品经理认为要重视反馈，不要只看效率。”

这留下一个正确结论，却删掉了改变判断的具体机制。

## 更完整的提炼

**机器排序缩短处理时间，不足以证明整个流程改善。** 在这个合成试点里，复核者发现关键事项更容易漏看。这意味着效率指标可能遮住任务真正的损失：人处理得更快，却没接住重要事项。

团队因此把复核者的异议转成下一轮验证的问题：关键事项的漏检是否增加，排序调整后能否改善。试点尚未证明可以扩大，材料也没有足够样本信息支持效果量化。

这一写法保留“做了什么→发现了什么→为什么原指标不够→下一步检验什么”的关系，同时保留未知范围。关键不是比旧句子长，而是读者能够解释决定为什么改变。

## 编辑分析的边界

可以另提“这类试点应同时看速度与关键漏检”的方法建议，并标为Agent分析；不能改写成用户已经采纳，也不能凭空补充样本数量、提升百分比或已经成功上线。

## 可变字段的合成审核案例

1. 署名文章仅有作者与原文链接：显示作者，不生成讲者/访谈人。来源无日期时不猜。
2. 访谈只取得中文编译：讲者/访谈人有证据可列，来源明确为实际读取的编译；原视频链接不代表已核听。将编译改成直接引语应判待补充。
3. 机构报告有摘要无全文：列机构和摘要链接，交付摘要整理而非完整报告提炼；不得编造样本口径。
4. 多来源意见相反：各列主体，正文保留分歧；合成一条共同结论应判待补充。
5. 用户只说“保存”：不新增“我的判断”；已有AI应用建议须归属整理者。
6. 排版/目录测试通过但遗漏关键反例：页面可记通过，内容仍待补充，不得发布为完整提炼合格稿。
