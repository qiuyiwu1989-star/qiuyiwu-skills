# 阅读档案详情页：结构与可变字段 v1.0

用于生成或修改知行档案reading页面，不用于将所有材料强行改成访谈。

## 固定阅读顺序

标题 → 一句话导读 → 日期/人物/来源区 → 全篇概述 → 分主题提炼 → 可选整理者分析 → 可选来源材料与相关档案。

导读用一句话说明关注点；概述通常2—3段讲清核心问题、主要论证与结论边界。两者不重复粘贴，不使用“AI不在算法而在物理”等超出材料证据的绝对结论。正文结构由材料逻辑决定，不强制章节数量。概述与分析使用h2，主题内h3最多两级目录。

## 固定组件，可变角色

| 材料类型 | 人物/机构字段 | 来源链接角色 | 需保留的限制 |
|---|---|---|---|
| 署名文章 | 作者；有证据才列编译者 | 原文、译文或转载 | 实际读到的是全文还是节选 |
| 访谈/对谈 | 讲者、访谈人；多人按真实角色分组 | 原视频/音频、转录、中文编译 | 转录不等于核听；不能把转述当逐字引语 |
| 研究/行业报告 | 作者或发布机构；多人名单可收至文末 | 原报告、摘要、数据附件 | 样本、研究时间、统计口径与方法限制 |
| 无署名资料/网页 | 有证据的发布机构或账号；未知角色省略 | 实际取得的网页或文件 | 不从域名猜作者；来源不完整要说明 |
| 多来源综合 | 分别列出来源主体，不伪造共同作者 | 多个来源分别命名，正文按需关联 | 分清共识、分歧、编者综合 |

组件固定的是语义与布局，不是每篇必须填满所有角色。角色按来源真实定义；主持人、讲者、作者、译者、发布账号不能互相替代。用户与AI自己的研讨应进入研讨类型，不能硬套外部阅读。

日期：原文发布日期与本次整理日期分开，页面显示日期须与结构化数据一致。缺原文日期时写“原文日期未提供”或省略该项，不猜测、不用抓取时间冒充发布时间；机器time仅在真实日期已知时填写datetime。原日期有冲突则保留差异。展示角色可多于后端字段，不能发明后端必填字段。

来源：优先真实原始来源，同时标明本次实际读取的是哪一份。没有原文只拿到编译时，编译就是实际依据，原文链接不代表已读。多份材料各用可辨认名称，禁止几个链接都叫“阅读原文”。来源限制普通文字一次说明；不得恢复重复字段清单、档案信息折叠栏或长信源徽章。

## 观点归属

“整理者分析与待验证问题”可省略；仅保留有增量和依据的分析，不默认映射用户项目。已有历史“读后判断”注明原整理者，不能静默变成用户观点。“我的判断”仅在用户真实表达时出现，保留来源与时间；保存、阅读、要求绘图或发布不代表认可全部结论。

原材料全文不是必填。先确认实际取得的材料类型及展示范围；不能把编译叫原始访谈稿。公开全文需要相应授权或许可，不能以附录方式复制未授权作品；可以提供链接和必要短摘录。未得到材料时不显示空附录。

## 设计与接入

正式样式依据qiuyiwu.com/design-system.html。页面引用/assets/v3-tokens.css和/vault/reading-detail.css?v=7，正文宋体、二级标题700；导航/来源/表格使用共享黑体。加载/vault/reading-toc.js?v=2，桌面固定目录、移动折叠，原文完整标题与章节hash保留。后续版本先查reading-detail-v1.txt，不复制旧页面独立CSS或自造字体/色板。

组件类：body.vault-reading-detail、main.reading-detail、reading-lead、reading-source、dl.reading-dates（dt/dd/time）、dl.reading-people（dt/dd）、reading-source-links、source-kind、section.reading-overview、reading-table、editorial-label。共享脚本生成目录，无需复制导航。样例见assets/reading-detail-example.html。

script#vault-reading-metadata、type=application/json：content_type=reading_archive、date=整理日期、summary=导读、tags=数组。人物等展示字段暂不假装全部有后端独立字段。JSON嵌入时将<转义为\\u003c，HTML文本/属性分别转义。日期/来源角色/概述/目录必须与正文一致。文稿元数据仍遵循docs/contract-v1.md；元数据保留不等于前台显示字段清单。
