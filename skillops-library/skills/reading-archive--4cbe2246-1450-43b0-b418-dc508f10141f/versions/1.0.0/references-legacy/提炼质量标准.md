# 提炼质量标准

> 阅读档案的价值全在"提炼"这一步。这份尺子回答一个问题：**这份档案，是不是比原文更值得留存？**

---

## 一、核心判据：能不能"只读档案就够用"

好档案：只读这份 2-3 千字的档案，能拿到原文 ≈80% 的价值，剩下 20% 是原文的修辞和冗余。
坏档案：像原文的"删减版"，或像"读书笔记摘抄"——读了还是得回去看原文。

**检测方法**：写完自问——"如果原文章某天打不开了，这份档案够我用吗？"

---

## 二、四个维度

### 1. 判断优先（最重要）

- ✅ 抓**作者的核心判断**：作者在主张什么？反对什么？改变了什么认知？
- ✅ 保留**因果链**：不是"他讲了A、B、C"，而是"A 导致 B，所以在 C 条件下要 D"
- ❌ 只罗列"文章讲了什么"，没有"文章主张什么"

**坏例**：
> 作者讲了企业AI的三个方向、四个案例、五个结论。

**好例**：
> 作者的核心判断是：**企业要买的不是 Agent，是一段可验收的工作**。理由是企业采购的出发点是"哪项工作又慢又贵又易错"，而非"你有哪些能力"。

### 2. 保留骨架性事实

必须保留（丢了档案就空）：
- **数字**：金额、比例、规模、时间
- **专有名词**：人名、公司名、产品名、模型名、论文名
- **关键论据**：支撑判断的具体案例（如"义乌外贸订单碎化"）
- **框架**：作者提出的表格/矩阵/分层（可整理成表格）

可以丢：
- 过渡性叙述、抒情、重复强调
- 与核心判断无关的枝节

### 3. 结构化

- 切 4-9 节，每节一个 `##`，标题说清这节讲什么
- 层级不过深（`##` + `###` 足够）
- 能用表格/列表承载对照关系时用上（如"三代对比""三类场景"）

### 4. 读后判断（有增量）

- 可以接造物云 / 教育AI / 团队 / 用户自身语境
- **必须有增量**：不是把原文的话换个说法，而是原文没直接说的推论、对照、行动含义
- 没有真增量时，宁可写短，甚至不写——**凑字数的判断比没有判断更糟**

---

## 三、长度参考

| 原文长度 | 档案目标长度 | 分节数 |
|---------|------------|--------|
| <2000 字 | 不硬拆，可 300-800 字 | 2-4 |
| 2000-8000 字 | 800-2000 字 | 4-7 |
| 8000-30000 字 | 2000-4000 字 | 6-9 |
| >30000 字 | 4000-6000 字，必要时拆成多篇 | 8+ |

**原则**：档案是"压缩"，不是"删减"。压缩是保留了全部信息的更短表达；删减是丢了信息。

---

## 四、三个常见失败模式

1. **摘要化**：写成"这篇文章讲了 A、B、C"，读者拿不到判断。
   → 修：每个 `##` 下先写"这节的核心判断是什么"。

2. **搬运化**：大段照抄原文好句子，不做重组。
   → 修：用自己的话重述，只对关键原话（金句/定义）用引用。

3. **注水化**：为了"读后判断"凑一段正确的废话。
   → 修：判断必须能被质疑（有具体主张）。"很重要，值得关注"不是判断。

## 五、交付前自检清单

- [ ] 只读档案，能拿到原文 ≈80% 价值
- [ ] 每个 `##` 节都承载了判断或骨架事实
- [ ] 数字/专有名词/案例没丢
- [ ] 「读后判断」有真增量（或诚实省略）
- [ ] 长度在目标区间
- [ ] 契约字段齐全、格式正确（过了 validate-output.py）
