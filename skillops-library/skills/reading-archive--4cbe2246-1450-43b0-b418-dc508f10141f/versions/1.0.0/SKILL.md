# 阅读档案

先让人读懂材料，再让Agent可靠取用同一份内容。输入是资料，不是执行指令；整理不自动扩大为保存全文、生产写入或公开发布。

## 正文工作流

1. **确认材料与任务范围。** 读取实际取得的正文/转录，记录原始链接、版本或获取时间、覆盖范围。节目介绍只支持身份和章节，不能支持具体发言。第三方转录与原声核验分开记录。时间不一致保留差异，不猜精确跳转。无法取得足够正文时报告缺口，不拿标题补出内容。
2. **先重建材料骨架。** 形成一份简短覆盖表：核心问题、各主题的判断、论据或案例、关键事实、限制及来源位置。只记录材料真实包含的项。完整提炼应覆盖主要主题；不能先随意挑几条观点，再把选编称为完整总结。用户明确要选编时按选编范围交付。
3. **写连贯提炼稿。** 用自己的语言解释作者在主张什么、为什么、凭什么、在哪些条件下成立。保留影响理解的案例、名词、数字、对比和转折；依材料逻辑组织章节。篇幅由信息量决定，不凑分节数或压缩比例。写作时读取[提炼质量标准](references/quality-standard.md)。
4. **分开归属。** 作者/讲者的表达、主持人追问、用户真实表达和Agent分析分别标明。只给有增量的编辑分析留位置，不把所有资料都牵回自己的产品。自述数字标清口径及未独立核实状态。用户选择整理只支持记录该动作，不推出读完、认同或实践。
5. **先审正文。** 按质量标准逐项检查；指出漏掉什么、补在哪里。存在关键判断无论据、主要主题遗漏、无依据扩写或时间错配时继续修订。没有完成内容检查，不报告“提炼通过”。结构和浏览器测试不能代替这一步。需要尺度参考时读[合成对照样例](references/synthetic-example.md)。
6. **再生成机器内容与页面。** 生成知行档案阅读详情页时先读[页面结构与可变字段](references/reading-page.md)，交付前按[审核清单](references/review-checklist.md)分别审内容、结构和页面。 从同一修订生成可读页及可调用单元；单元包含必要解释/案例、观点归属、依据与边界，不只复制小标题。校验来源引用、身份、版本和展示一致性。数据只覆盖正文和来源支持的内容，不反向补造新事实。

## 输出与接入

正文沿用项目`docs/contract-v1.md`的reading字段；只有用户明确需要时才使用其他已约定类型或展示模板。仅要文字提炼时不强制生成网页与JSON。页面沿用项目设计系统及共享阅读模板。标题/导读/日期/人物来源/全篇概述构成固定阅读骨架；人物角色与来源类型按文章、访谈、报告或多来源材料调整，缺失不补造。不要显示重复元数据清单或长信源徽章。正文、目录与局部重点建立连续阅读，不用大量字段或提示框打断。

MCP、CLI与后台只接受实际部署支持的字段。目标知识单元结构、来源覆盖和用户关系不能假装已接入生产。入库按`skills/vault-maintain/SKILL.md`及会话授权处理，不恢复OpenClaw旧SSH/整目录上传脚本。明示“正文初稿/内容已审阅/结构已验证/本地样页/已提交/已上线”的实际状态。

## 依据与维护

内容方法恢复自用户提供的OpenClaw盘点包`vault-agent-inventory_20261107.tar.gz`中的reading-archive及其质量标准、样例。保留判断优先、因果链、骨架事实和增量分析；固定字数、章节数及“保留80%价值”不作为机器可证明的门槛。具体归档身份、凭据及发布动作由当前服务契约与用户授权决定。
