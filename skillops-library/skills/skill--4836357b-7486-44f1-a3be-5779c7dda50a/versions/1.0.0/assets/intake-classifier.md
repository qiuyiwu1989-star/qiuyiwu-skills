# 意图识别引擎 — 分类规则与信号词库

## 六类内容的核心信号

### T1 · 会议洞察（meeting-insight）

**核心特征**：有「时间 + 人物 + 议题」结构，或明确标注为某次会议/讨论的记录。

**强信号词**（出现任一即可判定）：
- 会议、开会、讨论了、聊了、沟通、碰头、复盘
- 参会人员、与谁谁谁、昨天的/今天的/上午的
- 决定了/决策/结论/行动项/下一步

**典型输入形态**：
- 一段会议录音转写稿（有大量口语）
- 手写的会议要点（项目符号 + 决定事项）
- 「刚刚和[人名]聊了[主题]，主要结论是……」

**领域细分 → feishu_path**：
- 造物云/AIIP 相关会议 → `项目知识库/造物云/会议记录`
- 永乐学堂相关会议 → `项目知识库/永乐学堂/会议记录`
- 略懂AI 相关会议 → `项目知识库/略懂AI/会议记录`
- 浙大/MBA/课程相关 → `教学知识库/[课程名]/会议记录`
- 无明确项目 → `洞察与外部知识/会议洞察/[YYYY]/[MM]`

---

### T2 · 概念/想法（concept）

**核心特征**：碎片化的认知、新想法、理论推演、观察洞察——没有明确来源，是「邱懿武自己的思考」。

**强信号词**：
- 我在想/我觉得/我发现/有个想法
- 是不是可以/应该/能不能
- 有一个模型/框架/规律
- 其实……（开头的思考性表达）
- [新造词或自创概念名称]

**与其他类型的关键区别**：
- vs `external-knowledge`：无来源标注，是自己的思考而非摘录他人
- vs `topic-card`：没有「写这篇文章」的意图，而是「记录这个想法」
- vs `project-knowledge`：不是具体项目的决策/经验，而是可迁移的认知

**领域细分 → feishu_path**：
- 关于 AI 认知/教育 → `方法论与认知/AI认知框架`
- 关于创新/创业 → `方法论与认知/InnoLab`
- 关于写作/内容 → `方法论与认知/推导式写作`
- 关于教育理论 → `方法论与认知/教育理念`
- 其他 → `方法论与认知/散思录`

---

### T3 · 外部知识（external-knowledge）

**核心特征**：来源于他人的内容——文章、书籍、演讲、报告、对话摘录。

**强信号词**：
- 看到一篇/这篇文章/转发给我
- URL/链接/http
- [作者]说/[XX]提出/据[来源]
- 摘录/引用/这本书
- 报告显示/研究发现/数据说明

**处理重点**：不是复制内容，而是提炼「对邱懿武有用的洞察」。必须包含「可迁移的认知」字段。

**领域细分 → feishu_path**：
- AI/技术相关 → `洞察与外部知识/行业洞察/AI与技术`
- 商业/创业相关 → `洞察与外部知识/行业洞察/商业与创业`
- 教育相关 → `洞察与外部知识/行业洞察/教育`
- 文化/艺术 → `洞察与外部知识/行业洞察/文化与艺术`
- 书籍 → `洞察与外部知识/阅读笔记`
- 无明确分类 → `洞察与外部知识/行业洞察/其他`

---

### T4 · 项目知识（project-knowledge）

**核心特征**：与特定正在推进的项目直接相关——进展更新、关键决策、踩坑经验、可复用方法。

**强信号词/项目名称识别**：
- 造物云、AIIP、AI创意IP、角色孵化、数字藏品
- AIIP项目、垂类小红书、去中心化泡泡玛特、IP交易市场
- 永乐学堂、创新教育、任意门、王炸探索营
- 略懂AI、推导式写作、AI认知革命
- 浙大知识技能平台、ZJU Skill Hub
- 陈诗中、方颖、老蔡/蔡跃栋（人名出现暗示项目语境）

**与会议洞察的区别**：
- `meeting-insight` 关注「这次会议发生了什么」
- `project-knowledge` 关注「这个项目沉淀了什么可以复用的知识」
- 同一次会议记录处理完后，如果有可提炼的项目经验，可以额外生成一条 `project-knowledge`

**领域细分 → feishu_path**：
- `项目知识库/造物云/[策略|产品|运营|技术]`
- `项目知识库/AIIP/[策略|产品|运营|融资]`
- `项目知识库/永乐学堂/[课程|运营|教研]`
- `项目知识库/略懂AI/[内容策略|写作方法|渠道]`
- `项目知识库/浙大技能平台/[产品|商业|运营]`

---

### T5 · 选题卡片（topic-card）

**核心特征**：这是一个「值得写成略懂AI文章」的角度或素材，有明确的写作意图。

**强信号词**：
- 可以写、这个可以写成文章、选题、有一个角度
- 略懂AI、推文、公众号
- 「其实……」+ 反常识观点结构
- 数据/案例 + 分析框架 的组合

**与 `concept` 的关键区别**：
- `concept`：我想记录这个想法（存档为主）
- `topic-card`：我想写这个内容（写作为主）
- 当两者都有时 → 优先判断为 `topic-card`（写作意图比记录意图更稀缺）

**紧迫度评级（必须填写）**：
- ⭐⭐⭐⭐⭐：时效性强 + 素材充分 + 角度独特
- ⭐⭐⭐⭐：角度好但需要补充素材
- ⭐⭐⭐：方向对但还需沉淀

**feishu_path**：
- `内容创作库/选题库/待写`（默认）
- `内容创作库/选题库/[系列名]`（如果归属某个系列）

---

### T6 · 课程知识（teaching-knowledge）

**核心特征**：用于教学场景的知识——浙大MBA、中山MBA、永乐学堂、造物云内部培训。

**强信号词**：
- MBA、浙大、中山大学、学员、上课
- 教学、讲课、怎么讲、课件素材
- 案例、学员问题、学生的反应
- 永乐学堂的课、创新教育、任意门计划

**核心输出重点**：不只记录「讲了什么」，更要提炼「怎么讲更有效」「学员卡在哪里」「这个案例效果怎样」。

**领域细分 → feishu_path**：
- `教学知识库/MBA课程/[浙大|中山]/[模块]`
- `教学知识库/永乐学堂/[课程名]/[模块]`
- `教学知识库/造物云培训/[主题]`

## 歧义判断决策树

遇到两种类型信号共存时，按以下优先级决策：

```
内容含项目名 + 有URL来源？
  └─ 是 → project-knowledge（项目优先，摘录来源作为参考资料）

内容有会议时间/人物 + 含「可以写」？
  └─ 是 → 问一个问题：「这是会议洞察还是选题素材？」

内容像自己的想法 + 又有引用别人的部分？
  └─ 超过60%是自己的推演 → concept
  └─ 超过60%是摘录他人 → external-knowledge

内容像想法 + 也像可以写的选题？
  └─ 有明确文章角度 → topic-card（写作意图优先）
  └─ 没有明确角度 → concept
```

## 骨骼层分类（正交维度，叠加使用）

> 灵感来源：李继刚「问骨」方法论——每条知识追问它「凭什么成立」。
> 骨骼层不替代上面的六类分类，而是在六类之上再打一层标签。

### 三层骨骼

| 骨骼层 | 含义 | 判断标准 | 举例 |
|--------|------|---------|------|
| **L1 第一性原理层** | 这条知识的最终支撑是不可再拆的公理/规律/本质 | 追问"凭什么成立"3次后，答案变成一个无需证明的事实或定义 | "IP变现的本质是注意力变现"——无法再追问，这是定义 |
| **L2 方法论层** | 这条知识是一个可复用的操作框架/模型/流程 | 它告诉你"怎么做"，但"为什么这样做有效"需要追溯到L1 | "问骨=把idea映射到第一性原理第一层"——是方法，不是本质 |
| **L3 现象层** | 这条知识是观察到的事实/数据/案例 | 它告诉你"发生了什么"，但没有告诉你"为什么"或"怎么做" | "AIIP日会讨论了2小时没人提用户"——是观察，不是判断 |

### 判断方法：三次追问

对每条入库知识，连续追问3次"它凭什么成立"：

```
知识：用户会为AI生成的IP形象付费
  ↓ 凭什么成立？
第1层：IP形象有粉丝基础，粉丝愿意买单
  ↓ 凭什么成立？
第2层：用户分享IP形象能获得社交价值（身份认同/归属感）
  ↓ 凭什么成立？
第3层：人天然需要符号来表达自我身份 ← 第一性原理（L1）
```

**落在第几层断裂，就标记为哪一层：**
- 追问到第3层仍可回答 → L1（有完整的底层逻辑链）
- 追问到第2层断裂 → L2（有方法但缺本质支撑）
- 追问到第1层就断了 → L3（只有现象，没有判断）

### 标注格式

在入库时，骨骼层作为额外标签附加：

```
洞察标题：用户不会为无粉丝的IP付费
核心简要：IP变现的前提是注意力资产，不是图形资产
骨骼层：L1 第一性原理层 ← 新增字段
骨骼链：IP付费 ← 注意力变现 ← 符号身份表达需求
```

```
洞察标题：IP创作流程应该先选意图再选风格
核心简要：假设用户知道自己要什么，但这个假设未经验证
骨骼层：L3 现象层 ← 新增字段
骨骼链：先选意图 ← ❌ 第1层即断裂（凭什么用户知道自己要什么？）
```

### 骨骼层的用途

1. **检索过滤**：需要底层认知时只看L1，需要操作指南时看L2，需要案例素材时看L3
2. **知识审计**：定期检查L3太多而L1太少 → 说明"看了很多但没想透"
3. **关联发现**：不同主题的L1知识如果指向同一个底层原理 → 跨域关联机会
4. **写作选题**：L2+L3丰富但缺少L1的领域 → 值得深挖写一篇文章
