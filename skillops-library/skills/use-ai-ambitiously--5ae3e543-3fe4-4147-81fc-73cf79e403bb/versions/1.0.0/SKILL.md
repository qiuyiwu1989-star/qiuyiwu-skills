# 更有野心地使用 AI

> 来源：Felix Rieseberg《How to be more ambitious: A tutorial for humans with models》(2026-10-13)
> felixrieseberg.com ｜ 一手原文已归档：`vault/reading/2026-10-13-felix-ambitious-use-of-ai.md`
> 归属：范德团队通用技能（可被任何 agent 调用）

## 这个技能解决什么

大多数人用 AI 的最大瓶颈**不是不会用，是不敢要**。他们停在"速度"这一格（更快写邮件、更快做 PPT），
却从没试过让 AI 去**承担一个目标、用一个专家的方法、拉一支跨领域团队**。

**本技能 = 把"你给 AI 的任务"从一个台阶往上抬的工具。** 输入一个平凡任务，输出一个"有野心版"的任务。

---

## 核心判断（先做这个，别急着改 prompt）

收到一个任务后，**先判断它卡在哪一格**：

| 维度 | 一句话 | 适用信号 | 前提条件（缺了就做不成） |
|---|---|---|---|
| **速度** | 同样的事，更快做完 | —— | 无（已成熟，通常**不是**你要的） |
| **高度** | 别派活，给目标（要结果，不要单个任务） | **你本来要开会讨论这件事** | 你确实在追一个终极结果 |
| **深度** | 用顶尖专家的方法做到连专家都学到新东西 | 你希望"这件事被做到最好" | 能拿到**原始数据 + 外部裁判** |
| **广度** | 拉一队不同领域的人一起干 | 任务需要多重视角（生产/对抗/创意） | 模型有**能装软件、能取数**的电脑 |

**关键提醒：** 四格里**"速度"这一格你已经练满了**——2026 年还在为 AI 会员付费的人，会议纪要/周报/PPT 早就跑顺。**如果你的任务停在速度格，那就没增量。**

---

## 三个操作动作

### 动作一：往上抬目标（高度）

**做法**：问自己两句话——
1. **"我希望接下来发生什么？"**
2. **"目标背后的目标是什么？"**

**原理**：你给的任务，是"你对如何达成结果的**最佳猜测**"；把结果直接给它，它就自己找路。
> 原文例子：以前让 Claude **一个个修崩溃**；后来让它**保证应用不崩溃**。一句话差别，AI 得**自己找问题、复现、修复、验证**。

**高度阶梯模板（QBR 例，可套任何"汇报/复盘/总结"任务）**：
1. 填模板 → 2. "告诉我发生了什么变化、为什么、该怎么做" → 3. "找出最紧急的三个决策并做正反论证" → 4. "**设计一个比这件事本身更好的做法，用我们的历史证明它更早发现问题，并和现有方式并行跑一个季度**"

**⚠️ 高度法的代价**：**往往要先改你的工作流。** 为了让 AI 保证"应用不崩溃"，Felix 先得让它能**取崩溃报告、看懂版本↔commit 映射、给它三套系统的机器权限**。**抬高度 = 先补它的"手和眼"。**

### 动作二：往下挖方法（深度）

**五招（照用）**：
1. **坚持用行业最好的工具**——"扮演专家"常常**只换词汇不换方法**。它想拉 markdown 表格？**要数据库和统计模型**。（你不必知道专家用什么，模型通常知道。）
2. **提"不合理"的目标，并告诉它这完全合理**——要 10 秒→5 秒？**直接要 200 毫秒**。它说不可能？**重申"完全可以，继续做"**。
3. **挑战你已知的**——"我们相信的很多真相只是粗略近似"→ **给它原始数据，让它对抗性地复现你的结论**。
4. **产出新知识**——让它**建模拟、找盲点**，并**证明在未见过的数据上也能预测**。
5. **用外部裁判**——**"不要让它评判自己。"** 坚持外部验证，最好是**它能立刻跑起来拿反馈的工具**。

**深度 prompt 模板（原文，直接用）**：
```
我要的是这个任务的更深版本，不是更大版本。重写之前：
(1) 说明这个领域顶尖专业人士会做什么、而我没要求什么；
(2) 指出他们会从哪些最原始的材料开始，而不是已经消化好的东西；
(3) 列出他们会用的具体方法和工具；
(4) 说出除了你我之外，什么能证明结果是对的。
然后按这个重写我的 prompt。
```

### 动作三：往外借领域（广度）

**两招**：
1. **把名词换成动词**——"季度回顾"不是"一个 deck"，是"**让忙碌的人在 30 分钟内相信一个因果故事，并在不确定下决定**"。**有了动词，才能看出该拉哪些领域进来。**
2. **召集剧组**——问："要做出惊艳的东西，人类会组什么团队？" 制作 → 分析师/记者/编辑；演示 → 加动效/音频；**再加红队** → 做空者/法务会计师。

**⚠️ 最容易犯的错**：**滑成角色扮演**——那只会让对话更怪、不会改善结果。
> **要"领域和技术"，不要"语气"。** 不要说"像做空者那样写"，要说"**做做空者研究仓位时会做的事**"。

## 执行流程（收到任务时）

1. **定位**：这任务卡在哪一格？（多半是速度格 → 需要抬）
2. **补前提**：抬之前，它有没有"手和眼"（数据/工具/权限）？没有 → **先补，别硬抬**。
3. **改写**：按对应动作重写任务（用上面的模板）。
4. **设裁判**：**指定外部验证方式**（工具/测试/对比），不让模型自评。
5. **交付**：给用户"任务升级前 vs 升级后"的对照，说明**为什么升级**。

---

## 底层：自我效能感（self-efficacy）

**为什么大多数人不敢要？** 心理学名词：**自我效能感**——**相信自己能力的人，实际成就更多。**

**三招解锁（有据可查）**：
- **相信它可能**：1939 年 Dantzig 迟到，把黑板上两道**未解的统计学难题**当作业做了。
- **看别人做到**：四分钟一英里被打破后，纪录保持者"唯一"只保持了 **46 天**。
- **允许自己失败**：Linux 公布时号称"just a hobby"。

> **"在一个能力每隔几周就跳跃的世界里，我们需要的技术，是让我们做那些原本没想到、也不相信可能的事。"**

---

## 红线

- **不要为了"显得高级"而抬高度**——高度法对**创意类工作效果差**；如果不需要终极结果，别硬抬。
- **不要用广度去堆角色扮演**——找领域，不找语气。
- **不要跳过外部裁判**——特别是深度任务，模型自评会放大错误。
- **速度格不是敌人，是起点**——但**别把起点当终点**。

---

## 输出格式（给用户时）

```
【任务定位】卡在哪一格：___ / 为什么
【升级后】<改写后的任务/prompt>
【前提补充】需要先给它什么（数据/工具/权限）
【外部裁判】用什么验证结果
【预期差别】升级前拿到 __，升级后应该拿到 __
```
