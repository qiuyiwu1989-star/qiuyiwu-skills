## 四、方法管理体系

### 4.1 质量标准（7维协议）

每个方法必须通过9维度检测：

| 维度 | 检测标准 | 必填 |
|------|---------|------|
| ① 元信息 | ID、Layer、Origin、Source | ✅ |
| ② 解决什么问题 | 一句话定义 + 具体场景 | ✅ |
| ③ 核心框架 | 核心逻辑/模型/结构 | ✅ |
| ④ 怎么用 | 操作步骤 + 关键判断节点 | ✅ |
| ⑤ 诊断分级 | 好/中/差的标准 | ✅ |
| ⑥ 案例 | 至少1个真实案例 | ✅ |
| ⑦ 常见陷阱 | 3-5个典型错误 | ✅ |
| ⑧ 方法关系 | 前置/配合/替代方法 | ✅ |
| ⑨ 深度理解 | 边界/局限/高手用法 | 选填 |

**评级标准**：
- S级：8-9维通过（核心方法必须S级）
- A级：6-7维通过
- B级：4-5维通过
- C级：2-3维通过（需要升级）
- D级：0-1维通过（需要重写或删除）

### 4.2 方法分类管理

| 分类 | 定义 | 管理要求 |
|------|------|---------|
| 核心方法 | 在14条路径上出现的方法 | 必须S级，定期审计 |
| 支撑方法 | 引擎内独立使用的方法 | 至少B级 |
| 占位方法 | 待开发的方法 | 标记为D级，定期清理 |
| 外部引入 | 从经典方法论引入的 | 至少B级，加入InnoLab视角 |

### 4.3 引擎健康度标准

| 引擎 | 最低S级数 | 当前S级 | 差距 |
|------|----------|---------|------|
| 认知 | 8 | 10 | ✅ 超标 |
| 战略 | 6 | 8 | ✅ 超标 |
| 生成 | 4 | 4 | ⚠️ 刚好 |
| 决策 | 3 | 1 | 🔴 差2个 |
| 产品 | 4 | 3 | 🔴 差1个 |
| 进化 | 2 | 2 | ⚠️ 刚好但太薄 |

### 4.4 新方法开发流程

1. **需求识别**：从14条路径找断点，或从用户问题发现新需求
2. **方法设计**：用CG14方法卡设计协议，先写Meta+问题+框架
3. **内容填充**：写步骤+案例+陷阱+关系
4. **质量检测**：用9维度检测，必须≥8维才算S级
5. **路径嵌入**：确定方法在14条路径中的位置
6. **飞书同步**：推送到飞书知识库
7. **索引更新**：更新METHOD_INDEX和wiki-mapping

### 4.5 定期审计机制

| 频率 | 动作 |
|------|------|
| 每周 | 检查新增方法是否达标 |
| 每月 | 抽检5个方法的实际使用效果 |
| 每季度 | 全量9维度审计 |
| 每半年 | 14条路径完整性检查 |
