# 技能：方法卡锻造（Method Card Forge）

## 触发词

以下表述会触发此技能：

| 触发词 | 示例 |
|--------|------|
| 写方法卡 | "帮我写一个关于XX的方法卡" |
| 升级方法 | "把这个方法升级到S级" |
| 方法文档 | "帮我整理一下这个方法的文档" |
| 7维模板 | "用标准模板重写这个方法" |
| 方法锻造 | "锻造一个新方法" |

## 技能定位

**做什么**：将模糊的方法论想法/旧格式文档，锻造为符合7维标准的结构化方法卡。

**不做什么**：
- 不做方法论的原创发明（那是懿武的工作）
- 不做行业分析（那是ST02的工作）
- 不做内容润色（那是CG12/CG13的工作）

## 7维标准模板

```markdown
# [方法名]（[英文名]）

## Meta
- ID: [编号]
- Engine: [引擎: cognition/strategy/generation/decision/product/evolution]
- Layer: [层级: L2/L3/L4/L5]
- Origin: [原创/改编/经典]
- Source: [出处]
- Version: [版本号，如 v1.0.0]

---

## 1. 解决什么问题
- **一句话定义**：[这个方法到底解决什么痛点？用一句话说清楚]
- **触发场景**：[什么时候该用它？列出3-5个具体场景]
- **不适用场景**：[什么时候不该用？列出2-3个场景]
- **与相邻方法的区别**：[和类似方法有什么不同？]

## 2. 核心框架
- [核心逻辑/模型/结构]
- [可以用图示/表格/公式表达]
- [必须能用一页PPT展示]

## 3. 怎么用
- **Step 1**：[具体动作] — [关键判断：需要人做什么判断？]
- **Step 2**：[具体动作] — [关键判断]
- **Step N**：[具体动作] — [关键判断]
- **输出物**：[用完这个方法，产出什么？]

## 4. 诊断分级
| 等级 | 标准 | 典型表现 |
|------|------|---------|
| L1 | [最低标准] | [具体表现] |
| L2 | [进阶标准] | [具体表现] |
| L3 | [高阶标准] | [具体表现] |
| L4 | [专家标准] | [具体表现] |

## 5. 案例
### 案例1：[真实案例名称]
- **背景**：[什么场景、什么问题]
- **过程**：[怎么用这个方法的，关键步骤]
- **结果**：[效果如何，数据/结论]
- **复盘**：[用得好在哪、差在哪]

## 6. 常见陷阱
| 陷阱 | 表现 | 对策 |
|------|------|------|
| [陷阱1名称] | [具体表现] | [怎么避免/补救] |
| [陷阱2名称] | [具体表现] | [怎么避免/补救] |
| [陷阱3名称] | [具体表现] | [怎么避免/补救] |

## 7. 方法关系
- **前置方法**：[用这个方法之前，先用什么？]
- **后续方法**：[用完这个方法之后，接着用什么？]
- **组合路径**：[在哪些路径上出现？标注路径名]
```

## 执行流程

### Step 1｜确认输入类型

判断用户给的是哪种输入：

| 输入类型 | 处理方式 |
|---------|---------|
| 新方法想法 | 从Step 2开始，完整锻造 |
| 旧格式文档 | 从Step 3开始，重新组织 |
| 已有方法升级 | 从Step 4开始，补缺维度 |

### Step 2｜填写元信息

- ID：按引擎分配（CG/ST/GN/DC/PD/EV）
- Engine：根据方法的主功能判断
- Layer：L2(工具)/L3(方法)/L4(框架)/L5(系统)
- Origin：原创(懿武)/改编(基于经典改造)/经典(直接引入)

### Step 3｜锻造"解决什么问题"

**核心问题**：这个方法到底解决什么痛点？

检查清单：
- [ ] 一句话定义是否说清了"解决什么"而非"是什么"
- [ ] 触发场景是否具体（不是"战略分析"而是"要判断AI是否会重构某个行业"）
- [ ] 不适用场景是否明确（比适用场景更重要）
- [ ] 与相邻方法的区别是否有判断（不是罗列，是比较）

### Step 4｜锻造"核心框架"

**核心问题**：这个方法的核心逻辑是什么？

检查清单：
- [ ] 能否用一句话概括框架
- [ ] 能否用一张图/表展示
- [ ] 是否有明确的输入→输出
- [ ] 是否有关键概念的定义

### Step 5｜锻造"怎么用"

**核心问题**：看完就知道怎么用吗？

检查清单：
- [ ] 步骤是否具体（不是"分析需求"而是"列出5-8个关键假设"）
- [ ] 每个步骤是否有"关键判断"标注
- [ ] 最后是否有明确的输出物
- [ ] 步骤数量是否合理（3-7步，太多记不住）

### Step 6｜锻造"诊断分级"

**核心问题**：用得好不好，有标准吗？

检查清单：
- [ ] 是否有4个等级（L1-L4）
- [ ] 每个等级是否有"标准"和"表现"
- [ ] L1是否足够低（新手可以达到）
- [ ] L4是否足够高（需要深度理解）

### Step 7｜锻造"案例"

**核心问题**：有真实案例可以参考吗？

检查清单：
- [ ] 案例是否真实（不是"假设有一个公司"）
- [ ] 是否有背景/过程/结果/复盘四个部分
- [ ] 结果是否有数据或具体结论
- [ ] 复盘是否指出了用得好/差在哪

### Step 8｜锻造"常见陷阱"

**核心问题**：这个方法最容易犯什么错？

检查清单：
- [ ] 是否有3-5个陷阱
- [ ] 每个陷阱是否有"表现"和"对策"
- [ ] 陷阱是否具体（不是"分析不够深入"而是"模块三描述AI功能而非变量"）
- [ ] 对策是否可操作

### Step 9｜锻造"方法关系"

**核心问题**：这个方法跟谁配合？

检查清单：
- [ ] 前置方法是否明确
- [ ] 后续方法是否明确
- [ ] 是否映射到了14条组合路径

### Step 10｜质量检测

用9维度自动检测：

```
✅ Meta完整（ID/Engine/Layer/Origin/Source/Version）
✅ 问题定义（一句话+场景+不适用+区别）
✅ 核心框架（有框架图/表）
✅ 执行步骤（有Step+关键判断）
✅ 诊断分级（L1-L4）
✅ 案例（真实案例）
✅ 陷阱（3+个，有对策）
✅ 方法关系（前置+后续+路径）
✅ 深度理解（边界+高手用法）
```

评级：S(8-9维) / A(6-7维) / B(4-5维) / C(2-3维) / D(0-1维)

## 输出格式

锻造完成后，输出两个文件：
1. **方法卡文件**：`methods/[engine]/[method-id].md` — 完整的7维方法卡
2. **同步到飞书**：如果用户要求，推送到飞书知识库

## 注意事项

- **案例必须真实**：宁可没有案例，也不要编造案例
- **陷阱必须具体**：不要写"分析不够深入"这种空话，要写"模块三描述AI功能而非被AI改写的变量"
- **诊断分级必须有梯度**：L1和L4之间必须有明显差距
- **不适用场景比适用场景更重要**：知道什么时候不该用，比知道什么时候该用更难
- **方法关系必须映射到路径**：不在任何路径上的方法，是"孤岛方法"，价值有限
