# 演讲实录（Speech Recap）

> 用途：把【录音/文字记录 + 课件】→ 一篇可发布的「现场实录」HTML
> 归属：范德团队技能（任何 agent 可调用）
> 服务对象：邱懿武（qiuyiwu.com 的 `/speakings/` 实录栏目）
> 验证案例：2026-10-25《OPC与创新创业教育》（见 gates 记录）

## 0. 定位（先读这条，它决定一切）

**这是记录，不是营销稿。**

三条编辑纪律（违反即不合格）：
1. **修口误、顺逻辑、回归真实**——保留讲者**第一人称口吻和真实措辞**。
2. **不做钩子标题、不替讲者拔高、不杜撰细节/数据/案例。**
3. 标点：中文正文一律用**弯引号""**；直角引号「」只用于三种例外（标题引用 / 新造术语 / 品牌固定写法）。

> 判断标准：读者读完，应该觉得"**这个人当时是这么说的**"，而不是"**这篇写得真好**"。

---

## 1. 输入（三样）

| 输入 | 必需 | 说明 |
|---|---|---|
| **逐字稿** | ✅ | 录音转写，或飞书「文字记录」。**逐字稿是唯一真源** |
| **课件** | ✅ | PDF/PPT——抽帧做配图，并作为章节/术语的核对依据 |
| **场合说明** | 建议 | 场合名、听众、日期；**哪些是"计划"而非"已实施"**（必须标） |

⚠️ **转写会引入缺失**：飞书文字记录通常**不含讲者最后停播的部分**（如本次 OPC 实录缺了部分讲者段落）。**若发现内容不完整，先告知用户，不要自己补。**

---

## 2. 流程（七步）

### 步骤 1：素材记账
- 逐字稿字符数、讲者发言段数（多人场只取目标讲者段落）
- 课件页数、可配图的页
- **明确记录"缺口"**（转写缺失/听不清/待核）

### 步骤 2：保真整理（核心，占 70% 工作量）
- **修**：口误、重复、口水词（诶/啊/就是说）
- **顺**：口语顺序 → 书面顺序（但**不改变原意**）
- **保留**：第一人称、真实措辞、原话里的力度（"我宁可不做"不要改成"我们审慎决策"）
- **不删**：实质内容
- **不加**：逐字稿里没有的判断/数据/案例

### 步骤 3：分节 + 配标题
- 每节一个 **`<h2 class="part" id="part-N">`**
- 标题**平实**（"一、我为什么不愿意只讲一人公司"），**不做钩子**
- **`id` 绝不能漏**——漏了会同时废掉：① 左侧目录渲染 ② 检索深链

### 步骤 4：控密度（每 300–500 字一个"视觉停顿"）
- 停顿 = **图 / `<h3>` / `<blockquote>`** 三种之一
- 实测公式：`正文去空白字数 ÷ 停顿数`，落在 300–500 为佳（<300 偏密也可接受，>500 必须补）
- 反例：曾有一篇每 3529 字才一个锚点，读者要滚 7 屏

### 步骤 5：配课件图
- 图从课件页导出，**webp** 格式
- 命名：`{slug}-{页码:03d}.webp`（如 `opc20261025-007.webp`）
- `<figure><img loading="lazy" src="fig/..."><figcaption>{说明} · 本场课件第 N 页。</figcaption></figure>`
- **图卡在"金句/关键判断"之后**，不是随便插

### 步骤 6：脱敏（⚠️ 只列不删）
- **不能自动删改**，必须产出**疑点清单**交人复核
- 必查项：
  - **客户名 / 合作方名**（"利丰"→"一家大型服装供应链企业"）
  - **人名**（团队同学→匿名；公开人物/主办方可保留）
  - **政治人物暗示**（最难——如"现在的总理啊，当时是我们的省长"这类，规则判不出）
  - **证件号/手机号/金额**（自估数字是否加"约"）
  - **"老登/中登/小登"** 等可能对号入座的措辞 → 提请注意
  - **计划 vs 已实施**（"收费培养的想法，还是当时提出的计划" —— 这类限定句**必须保留**）
- 输出格式：`【脱敏疑点】原文 __ → 建议 __（理由）`，**逐条列，不擅自处理**

### 步骤 7：套壳 + 校验 + 发布
- **套现成壳**（不要自创）：qiuyiwu.com 的 `/assets/recap.css` 三栏网格壳
- 结构六件必须齐（见第 3 节）
- 跑校验（见第 4 节）
- **发布前给用户确认**；动生产站前取得许可

## 3. 输出：结构六件（缺一即不合格）

来自线上 `check_recap_standard.py`：

| # | 件 | 判准 |
|---|---|---|
| 1 | **进度条容器** | `<div class="read-bar">` |
| 2 | **阅读脚本** | `/assets/recap-reader.js` |
| 3 | **统一顶栏** | `/assets/v3-shell.css` **且** `/assets/v3-ui.js`（两个都要） |
| 4 | **篇尾说明** | `class="foot"`（用 `<p>`，不用 `<footer>`，避免一页两个 footer 地标） |
| 5 | **三栏网格壳** | `class="r-shell"` + `id="r-toc"` + `id="r-atoms"` |
| 6 | **章标题** | 全部 `<h2>` 带 `class="part"` **且**带 `id` |

---

## 4. 校验脚本

**线上**（发布后跑）：
```bash
ssh <server> "python3 /var/www/html/pipeline/check_recap_standard.py"
```

**本地**（发布前自查，等价逻辑）：
```python
import re
h = open('index.html', encoding='utf-8').read()
h2 = re.findall(r'<h2\b[^>]*>', h)
art = re.search(r'<article.*?</article>', h, re.S).group(0)
text = len(re.sub(r'\s', '', re.sub(r'<[^>]+>', '', art)))
stops = (len(re.findall(r'<img\b', art)) + len(re.findall(r'<h3\b', art))
         + len(re.findall(r'<blockquote', art)))
ck = {
  'read-bar': 'read-bar' in h,
  'recap-reader.js': 'recap-reader.js' in h,
  'v3顶栏': 'v3-shell.css' in h and 'v3-ui.js' in h,
  'class=foot': 'class="foot"' in h,
  '三栏壳': all(k in h for k in ['class="r-shell"','id="r-toc"','id="r-atoms"']),
  'h2 part': bool(h2) and all('part' in x for x in h2),
  'h2 id': bool(h2) and all(' id=' in x for x in h2),
}
assert all(ck.values()), [k for k, v in ck.items() if not v]
print('密度:', text, '字 /', stops, '停顿 = 每', text//max(stops,1), '字（300-500 达标）')
```

## 5. 输出清单（交付给用户）

1. **实录 HTML**（结构六件齐、密度达标、图配好）
2. **脱敏疑点清单**（逐条，待人复核）
3. **缺口清单**（转写缺失/待核事实）
4. **密度报告**（每 N 字一次停顿）
5. （发布时）新的 `speakings` 目录 + 卡片索引更新

---

## 6. 红线

- ❌ **不做钩子标题 / 不替讲者拔高**（这是记录）
- ❌ **不杜撰细节、数据、案例**
- ❌ **不自动删改敏感信息**——只列疑点，人复核
- ❌ **不把"计划"写成"已实施"**
- ❌ **章标题漏 id**（会废掉目录+深链两样）
- ⚠️ **动生产站前必须取得许可**——先出稿，用户确认后再发布
