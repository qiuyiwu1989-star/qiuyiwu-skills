# 画图

**产物是一个文件，不是一个链接。**

```
<项目根>/docs/diagrams/YYYY-MM-DD-<主题>.html
```

单文件自包含：一个 HTML 里装下全部 CSS、JS、SVG。双击能开，断网能开，跟着 git 走，
换台机器 clone 下来还是那张图。

## 铁律

1. **不发 Artifact。** 除非用户在这一轮里明确说了「发个 artifact」「发布出去」「给我个链接」
   「要分享给别人」。默认路径永远是写文件。
   （Artifact 工具的默认说法是「交付物留在本地文件里等于没交付」——**这条对邱不成立，已推翻**。）
2. **不用 emoji。** 邱的全线铁律。状态、置信度、优先级一律用文字或形状表达。
   需要图标时用内联 SVG（lucide 的路径数据），不要字符图形。
3. **不引外部资源，除了字体。** 图片、图标、数据全部内联（data URI 或直接写进 HTML）。
   字体可以引 Google Fonts，但**必须给完整 fallback 栈**——断网时这张图不能垮：
   `font-family: "IBM Plex Sans", -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`
4. **用真数据。** 能查库就查库，能读代码就读代码。写不出真数字时标明「示例」，
   绝不拿编的数字冒充实测。图里每个数字都要能说出它从哪来。
5. **两种主题都要能看。** 见下面的「主题骨架」。

## 项目已有设计系统时，先用项目的

动手前先找：`CLAUDE.md`、`design-system` 相关文件、`tokens.css`、既有组件样式。
找到就用它的色板和字阶，本 skill 只补它没说的部分。

深脑（lengjing）有自己的设计系统 v3.1，画深脑的图时对齐它。

## 主题骨架

```css
:root {                      /* 亮色：完整定义每一个 token */
  --ground: …; --surface: …; --ink: …; --muted: …; --line: …;
  --accent: …;               /* 一个强调色，用在最该被看见的那一处 */
}
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { /* 只重定义 token，不写组件样式 */ }
}
:root[data-theme="dark"] { /* 同上，让显式切换也生效 */ }
body { background: var(--ground); color: var(--ink); }
```

**一个颜色的唯一定义不能待在媒体查询里**——那是最经典的「白底白字」bug。

## 画什么

图要让人看见**机制**，不是看见名词。一个写着「缓存」的方框比一句话的信息量还小；
请求穿过它的路径、它夹在哪两个存储之间、去掉它哪条箭头会消失——这些才是文字说不清的。

- **箭头必须有标签。** 没标签的箭头意思是「有点关系」；`写入`、`每 30 秒轮询`、`失败时回退` 才是信息。
- **对比方案就画差异。** 并排两个架构、改动前后、每个方案各加/减了哪条边。
  几个互不相连的方框不叫对比，那只是把选项列表重排了一遍。
- **复杂度配得上赌注。** 一跳的问题就是三个框；一次把写入改道过队列的迁移，
  队列、写方、读方、顺序箭头一个都不能少。
- **结构本身要是信息。** 编号（01/02/03）只在内容真的是序列时才用。
  分组、分栏、色块都同理——它们各自在断言一件事，断言错了比没有更糟。

SVG 用 `viewBox` 定尺寸、`currentColor` 取色、`<defs><marker>` 画箭头，
外面包 `<figure>` + `<figcaption>` 说清这张图在讲什么。

## 流程

1. **先想清楚这张图要回答哪一个问题**，用它当页面标题。
   标题是名字不是说明：「分析链路与 token 账」，不是「关于分析链路的一些说明」。
2. 查真数据（库 / 代码 / 线上），拿不到就标明是示例。
3. 写文件到 `docs/diagrams/YYYY-MM-DD-<主题>.html`。目录不存在就建。
4. 追加一行到 `docs/diagrams/README.md`（没有就建）：
   `- [2026-09-13 分析链路与 token 账](2026-09-13-分析链路.html) — 一句话说它回答什么`
5. 用 `SendUserFile` 把文件递给用户，并给出打开命令：

   ```bash
   open docs/diagrams/2026-09-13-分析链路.html
   ```

6. 提交进 git（跟着当前分支走，与代码改动同一次提交或单独一次，按上下文）。

## 不要做的事

- 不要为了画图去起 dev server。这是个静态文件，直接 open。
- 不要生成一堆散文再配一张图。**图不够用的地方才写字**，反过来不成立。
- 不要把同一件事在图里画一遍、在回答里又完整讲一遍。回答里只说图上看不出的结论。
- 不要画完就算完 —— 图里的每个判断都要经得起追问「这个数从哪来」。
