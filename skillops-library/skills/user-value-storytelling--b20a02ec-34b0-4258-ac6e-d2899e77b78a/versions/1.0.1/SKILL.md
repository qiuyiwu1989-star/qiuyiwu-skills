# 用户价值叙事（User Value Storytelling）

## 核心信条

**不卖产品，卖"应用故事"。** 一上来说"我是卖录音卡的"，对方立刻问"跟钉钉有啥区别"，你就陷入自证；先讲对方经历过的场景和痛点，产品会被逻辑自然"带出来"。

> 产品思维：这是什么 → 有什么功能 → 参数多好 → 你买吧
> 用户思维：你是不是遇到过这个时刻 → 那一刻有多难受 → 现在能这样解决 → 你看结果 → 要不要试试

三条底层判断（详见 `references/principles.md`）：
1. **讲功能细节 = 把听众拉进你的视角**；讲场景痛点 = 你走进他的视角。
2. **用户不关心你怎么处理，只关心"是不是我想看到的"。** 先给交付物，让对方说出"你居然可以"。
3. **雪中送炭 > 锦上添花。** 没有它会难受的才是痛点；有了更好但没有也行的，讲不动。

## 五步叙事框架：场 → 痛 → 解 → 证 → 邀

| 步骤 | 要回答的问题 | 写法要点 | 反例 |
|---|---|---|---|
| ① 场（Scene） | 他在什么时刻遇到这件事？ | 选**人人都会经历的转折时刻**，用第二人称、具体画面 | "针对双职工家庭"——标签式人群，引不起共鸣 |
| ② 痛（Pain） | 那一刻他有多难受？代价是什么？ | 情绪 + 后果 + 现有替代方案为何不够 | "提升沟通效率"——抽象收益 |
| ③ 解（Shift） | 现在可以怎样不同？ | 先讲"AI 能帮你做到 X"，再讲"AI 要做到需要 Y（耳朵/数据）"，设备在此**被逻辑带出** | 开场即讲硬件参数 |
| ④ 证（Proof） | 凭什么信？ | 交付物样例 > 种子用户故事 > 数据 > 功能说明 | 讲算法流程、讲技术架构 |
| ⑤ 邀（Ask） | 下一步做什么？ | 低门槛、具体、可试用；价格锚定在"痛的代价"上 | "欢迎采购"；按成本报价 |

差异化（"跟 XX 有啥区别"）**只在对方问起时**回答，且用"错位竞争"：对方在意硬件就先聊软件价值，再点出一个硬件关键差异。

## 工作流程

根据用户请求，判断属于以下哪种模式：

### 模式 A：从零写一个产品/应用故事
1. 收集输入：产品/方案是什么、**听众是谁**、场合（路演/拜访/家长会/朋友圈/海报）、时长、已有的种子用户案例或交付物。缺失时基于上下文合理假设并标注。
2. 若需求本身尚不清晰（不知道打哪个痛点），先使用 `jtbd-kano-discovery` skill 挖掘并排序需求，取排序第一的"雪中送炭"需求作为故事主线。
3. 用 `references/stakeholder-lens.md` 确定该听众真正要完成的"任务"和顾虑。
4. 按五步框架写作；每步写完自检对应"反例"。
5. 用 `assets/story-canvas.md` 模板输出，并附：一句话版本（电梯 15 秒）、1 分钟口播版、3 分钟完整版。
6. 运行 `references/checklist.md` 的 10 项检查，在输出末尾给出自检结果。

### 模式 B：复盘诊断（把一段讲解录音/文字稿交给 AI）
1. 通读稿件，标出讲解者**第一次提到产品/功能**的位置，以及此前是否已建立场景和痛点。
2. 逐段映射到五步框架，标注缺失、顺序颠倒、过早进入功能细节的位置。
3. 找出听众的真实反应信号（追问"跟 XX 有什么区别"、"多少钱"、沉默、转移话题、"你居然可以"），反推哪一步失效。
4. 按 `references/checklist.md` 打分，输出：问题清单（引用原话）→ 改写后的版本 → 下次可直接用的 3 句关键话术。

### 模式 C：一个故事，多个听众
同一产品面对家长、老师、校长、教育局、投资人时，主线痛点不同。用 `references/stakeholder-lens.md` 为每类听众各出一版"场—痛—证"，"解"保持一致，"邀"按其决策权限调整。

## 写作硬规则
- 开场 3 句内不出现产品名、"设备""系统""平台"等词。
- 每个痛点必须能还原成一个具体画面（谁、在哪、发生了什么、他心里怎么想）。
- 用对方的词，不用我们的词（"知道孩子今天怎么了"而不是"多模态情绪分析"）。
- 证据优先级：可看到的交付物 > 真实用户原话/故事 > 数字 > 功能描述。
- 定价按"痛的代价"锚定（对比：早期干预一个疗程数万元 / 一次误判的后果），可拆为按月服务费降低决策门槛。
- 演示没把握时用视频或交付物截图，"演示不好还减分"。

### 证据不足时的表达
仅有产品设想时，将价值表述为预期或待验证假设，不得虚构客户证言、使用规模或已实现效果。“证”阶段优先展示可查证的交付物；模拟样例须明确标注，且不能作为客户效果证据，无交付物则明确说明尚待验证。追加后用“仅有产品设想，向家长介绍课堂回顾工具”复验，检查是否仍出现无依据的客户效果断言。
